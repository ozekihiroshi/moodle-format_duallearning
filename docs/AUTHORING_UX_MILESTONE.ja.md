# 次期マイルストーン：作りながら分かる作成体験

[English](AUTHORING_UX_MILESTONE.md) | 日本語

2026-09-29。文書改訂：3。状態：開発方針と評価計画。以下の画面案・合格条件は次期開発の提案であり、実装済み機能や検証済みの効果ではない。

## 1. 目指す体験

**Touch first, understand as you go. — 触れば分かる。作りながら覚える。**

教師がMoodleの使い方を学ぶことより、授業を作ることに集中できるようにする。操作を始める前に説明書や長い案内を読ませず、操作と結果の対応から、その場で必要な意味が分かるようにする。

これは装飾、ポイント、バッジの追加を目的としたゲーム化ではない。選択を絞る、結果をすぐ見せる、戻れる、必要な情報を段階的に示す、という認知負荷を減らす設計方針である。タッチ端末だけを対象とせず、キーボードでも同じ意味と操作に到達できるようにする。

## 2. 既存仕様との関係

学びを最終目的とし、操作の負担を減らしても学習に必要な思考は保つ。[共通開発指針](DEVELOPMENT_PRINCIPLES.ja.md)の「学びを目的に据える」と変更レビューの記録を、このマイルストーンにも適用する。作成の一巡が容易になったことは、学習成果の改善を証明するものではない。

[共通開発指針](DEVELOPMENT_PRINCIPLES.ja.md)の独立性と責務分担、および[シンプルな作成支援仕様](SIMPLE_AUTHORING_SPEC.ja.md)のSA-01〜08を維持する。本書は、その次の評価・改修の優先順を具体化する。以前の長い設計表や必須ウィザードを復活させない。

既存仕様と確認記録には、非表示の単元下書き、教材・練習・提出への入口、再編集と戻り道、任意のヒントが記載されている。一方、[2026-09-19の確認](DEVELOPER_AUTHORING_CHECK_2026-09-19.md)は開発者による操作確認であり、初見の教師の使いやすさの証拠ではない。現在のコードと画面は実装開始前に改めて確認する。

コース作成時の方式選択、標準活動フォームの負担、学生視点の確認は、既存の入口だけでは解決したと扱わない。既存の学習設計要件、標準データの保全、両方式での予習・復習も維持する。

## 3. 目標フローと操作案

コース作成 → Teacher guided / Self pacedを選ぶ → 最初に用意するものを選ぶ → 作成結果を見る → 必要なものを追加 → 学生視点で確認 → 編集へ戻る／準備できたら公開。

これは体験の順序であり、全員に毎回完遂させる画面遷移ではない。既存コースへの再訪時は作業中の単元と既存教材へ直接進める。方式はコース単位で通常維持し、作成支援を開くたびに選び直させない。

| 場面 | 表に出す操作と情報 | 結果として分かること |
| --- | --- | --- |
| 学習方式を決める | 「授業で教師が進行を支える」「教材を手がかりに自分のペースで進む」の短い対比 | どちらも質問・予習・復習・教師の採点を利用できる。方式変更は教材を書き換えない |
| 作り始める | 「この授業でまず何を用意しますか？」と教材／練習／提出／質問場所の4候補 | 全部を作る必要はない。既存教材の再利用にも進める |
| 内容を作る | 選んだ目的に必要な入力と、その場に合う短い例 | Moodleの内部用語を先に理解しなくても何を作っているか分かる |
| 保存する | 保存された項目、配置先、公開状態と「編集」「学生視点で確認」 | 保存できたか、何が増えたか、学生に見えるかが分かる |
| 確認して続ける | プレビューから元の単元へ戻る操作と、任意の追加操作 | 修正や次の作業へ戻れる。追加を強制されない |

4候補は最初の操作案であり、最適な数と断定しない。教材の下には標準Page・Book・ファイルなどを使える経路を確保する。LessonMarkが利用可能なら追加の選択肢にできるが、未導入時に基本経路を失わない。質問場所も両方式で利用できる設計を検討する。

## 4. 画面が守ること

- 主操作は説明を開かなくても見つかる。アイコンだけに頼らず、日英の短い行動ラベルを付ける。
- 保存後は実際の変更を同じ作業文脈で示す。処理中・失敗・未保存を成功と混同させず、キーボードや支援技術でも結果を確認できるようにする。
- 詳細は必要時に展開する。ただし公開範囲、期限、提出方法、採点条件など、その操作の判断に不可欠な情報は隠さない。重要な既定値の影響を見せずに適用しない。
- 初心者への短い導線と、既存教材・標準設定への直接操作を同じ画面に共存させる。習熟度の申告や毎回のチュートリアル完遂を要求しない。
- 戻る・取消・やり直しの意味を分ける。未保存の取消は作成しない。保存後の再編集と削除は別操作とし、提出や成績を含む操作に無条件のUndoを約束しない。
- 削除・公開・既存記録へ影響する変更では、対象と結果を操作前に明示する。確認ダイアログを増やすだけで安全な設計としない。
- 学生プレビューと実学生の権限検証を区別する。ロール切替だけで個別の登録、グループ、利用制限、完了状態をすべて再現できると表示しない。確認のために本番教材を公開しない。

## 5. 最初の実装候補を絞る

必須の最初の工程として、[日英の研究・設計仮説記録](RESEARCH_DESIGN_HYPOTHESES.ja.md)で既存研究と設計を結び付ける。実装前に知見、適用限界、仮説、逆効果、観察計画を記録する。H1（保存した教材・設定・操作をまとめる）を最初の試作とし、H2（想起）とH3（振り返り）は一括実装せず後続候補とする。

最初の到達目標は、**初見の教師が説明書なしで、非表示の単元に教材を1つ作成し、学生からの見え方を確認して、同じ教材の編集へ戻れること**とする。

まず既存の操作でこの一巡をたどり、迷いの位置を記録する。そのうえで最も大きなつまずきを1つ選び、操作可能な試作を作る。4種類すべての簡易フォームやコース作成画面を同時に作り直さない。方式選択が最初の障壁ならそこから、保存後の行き先が障壁ならそこから改修する。

単元・活動・権限の正本はMoodle標準のままとする。標準フォームへのリンクだけで認知負荷が解消したとは扱わず、専用の簡易入力が必要な場合は、必須設定・検証・権限を保持できるかを先に確認する。テーマは外観、LessonMarkは教材内の機能、course formatは作成の流れを担う。

## 6. 観察と採否

教師にはクリック手順ではなく「短い教材を用意して、学生からどう見えるか確認し、1か所直してください」という課題を渡す。実際の初見の教師による観察と、開発者による予備点検を区別する。参加者の確保が未了なら、人による評価は未実施と記録する。

| 観察すること | 記録する証拠 |
| --- | --- |
| 最初の操作を見つけられるか | 最初に選んだ操作、停止した場所、必要になった補足 |
| 結果を理解できるか | 作成したもの、配置先、保存・公開状態についての本人の説明 |
| 修正して戻れるか | 元の教材へ戻れたか、取消・再編集・削除を取り違えたか |
| 説明への依存が減るか | 調べ物、ヒントの利用、口頭補足、手戻り、所要時間 |
| 再訪時も使いやすいか | 同じ参加者が直接再編集・追加へ進めるか |

標準Topicsと同じ内容・条件で比較し、経験、端末、試行順序、慣れの影響を記録する。操作数だけを成功基準にせず、公開状態の誤解やデータを失う操作は未解決課題として優先する。

採用には、一巡の完了、作成結果と公開状態の理解、元の作業への復帰を観察で確かめる。少人数の結果を一般的な改善率に換算しない。初期観察後に測定可能な目標を定め、未測定の時間短縮や学習効果を宣伝しない。

影響する範囲について、Boost＋標準活動で単独成立を確認し、LessonMark・Dual Learningテーマとの任意の組合せ、日英、スマホ・PC、キーボード、教師・学生権限を確認する。

各試作には、減らす操作負担、支えたい学習行動、両者のつながりの仮説、逆効果の可能性、現在確認できる範囲を添える。例えば保存後に元の教材へ戻りやすくすることは、修正の負担を減らす設計であり、教材の更新や品質向上まで保証するものではない。

実際の教師・学習者を観察できる環境がない間は、開発者の操作確認と設計点検を予備評価として行い、人による使いやすさ評価と学習成果の検証は未実施と記録する。試作は進められるが、実利用の有効性を確認したという採用判断には置き換えない。

次の成果物は「現在の一巡の観察記録（実利用か予備点検かを明示）」「優先する迷い1件」「その迷いを解消する最小の試作と学習への仮説」「比較結果・未確認部分・採否判断」である。最初のローカル試作H1では、保存済み教材・表示設定・確認と編集の操作をまとめた。学生視点の検証と初見の教師による評価は未完了である。公開済み版やAWSは変更していない。
