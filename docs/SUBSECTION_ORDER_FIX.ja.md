# サブセクションの次教材順序修正

対象: GitHub Issue #2。alpha4で、親章とサブセクションを含むget_cms()の列挙順を学習順と誤認していた。

Moodle 5.2の公開API sort_cm_array()を用い、活動を実際の表示順に並べてから既存の可視性・完了判定へ渡す。独自のID/教材名ソートや章の平坦化は行わない。課題一覧とショートカットも同じ表示順になる。

検査対象:
- overview::build()を通じた、自学自習・教師伴走の両モードのサブセクション順序。
- サブセクション移動、完了後の次教材、非表示の親、親の日時利用制限、削除処理中の子活動。
- 平坦なコースの次教材と全完了状態。
- Chrome受入テストで、両モードの学生の次教材リンクから子教材本文を開く。

元の診断スクリプトはget_cms()順を直接組み立てるため、修正後の合否判定には使わない。公開APIの回帰テストを判断基準とする。既存の公開Pythonコース・教材・学生の完了記録は変更しない。

## alpha6での完結

alpha5は概要だけを修正していた。教材下部の前後リンクと活動選択欄にも保存順が残ることがユーザー確認で判明し、PR #3で修正、main a61bf22へマージ済み。alpha6は両方の修正を初めて一つの公開ZIPに含める。既存alpha5のタグ・ZIPは変更しない。

自動検証は両モードの前進・後退の実クリック、先頭末尾、非表示・利用制限・削除中、平坦コース、テーマのコースインデックスとの共存を含む。PHP 8.3/8.4で20テスト100検証、Chromeで4シナリオ72ステップ。ユーザーによるChromeでの追加受入と自動試験は区別する。
