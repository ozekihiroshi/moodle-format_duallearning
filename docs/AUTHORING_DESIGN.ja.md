# 一単元で具体化する作成支援の詳細設計

**更新：本書の画面案と実装順は[シンプルな作成支援仕様](SIMPLE_AUTHORING_SPEC.ja.md)で見直した。** S1〜S3を長い必須フローとして実装せず、項目表は内部検討資料とする。最初は編集可能な本文ひな型から標準の非表示単元を作る。独自メタデータ・チェックリスト保存は保留。以下は判断の履歴として残す。

2026-09-18。状態：実装に向けた設計案。画面・項目は未実装。要求正本は[学習設計仕様](LEARNING_DESIGN_SPEC.ja.md)、現行との差は[棚卸し](REVIEW_FEATURE_INVENTORY.ja.md)を参照。

## 1. 設計上の決定

方式はコース単位、作成支援は単元（標準セクション）単位とする。最初に方式を選び、その方式の作成手順を表示する。単元ごとの方式設定は追加しない。

作成者に多数のMoodle機能の選択から始めさせず、「学生が何をできるようになるか」「教師がどこを支えるか」から必要な教材と活動を対応づける。既存の活動を選択し、不足する場合に標準の追加画面へ進む。入力しただけで教材品質が保証されたとは表示しない。

予習・復習は両方式の学習段階として扱う。方式の切替ボタンを学生画面に置かない。標準の教材編集・提出・成績・完了・利用制限を正本とし、同じ説明の二重入力を避ける。

## 2. 題材と範囲

既存の「第3章 中間実践課題A — 明日の追加配送先を決める」の第1段階、**原資料を変更せずに確認する**部分を一単元として詳細化する。

参照資産（ローカル `moodle-rescue`）：`sample-content/introduction-to-python/project-3a-brief-ja.md`、同 `project-3a-brief-en.md`、`docs/dual-learning-project-3a-design.md`。日本語版の例を使うが、製品UIは日英対応する。英語デモ画面・スクリーンショットは別課題。

- 到達目標：CSVを読み、全行・並べ替えた表・欠損数・地区名を、原値を変えずに確認できる。
- 作業成果：既存 `inspect_school_meals.py` の3関数。チェッカー結果はLab内の確認であり、Moodleの提出・成績ではない。
- 最終課題は既存の2ファイル提出・20/80点を維持する。この小単元だけで新たな必須提出を増やさない。
- 以下の「解説」「確認問題」は配置・加筆の設計案。現行コースにすべて存在するとは扱わない。
- Python Labはこの題材の作業先。フォーマット自体はPage、Book、ファイル、標準小テスト、課題等で成立させ、LessonMarkやLTIを必須にしない。

| 場面 | 教師伴走型：作成する案内 | 自学自習型：作成する案内 | 学生の行動・戻り先 |
| --- | --- | --- | --- |
| 開始・予習 | 「CSVの列名と目的を読んでおく。表記ゆれの扱いは授業で説明」 | 「列の意味を確認し、原値を変えない理由を例で読む」。前提のpandas説明を指定 | 導入教材を読む。前提が不明なら基礎説明へ戻る |
| 進行 | 「本時は3関数まで。教師が並べ替えの例を示した後に作業」 | 読込→別表の作成→地区名集計の順序と各入出力の例を説明 | 作業先を開く。中断したファイルは作業環境で再開 |
| 理解確認 | 教師が「前後空白を消してよいか」を問い、原資料保持を確認 | 同じ問いの回答と理由を教材または標準小テストに用意 | 誤答なら原値保持の解説へ。再挑戦の可否は小テスト設定に従う |
| つまずき | 授業中の質問方法と授業外の質問先を案内 | 行数違い→読込説明、原値変化→コピーの説明、解決しない→質問先 | 具体的な説明に戻り、修正・再実行する |
| 終わり | 教師と出力を確認。次時の配送判定へ | 期待する出力とチェッカーを照合し、第2段階へ | この段階では提出不要。最終提出先は全体課題として案内 |
| 復習 | 授業で扱った理由・例を記録し、終了後も閲覧可能にする | 同じ解説・誤答時の戻り先を再利用 | 完了を取り消さず再閲覧。最終提出後は課題画面で講評を見る |

## 3. 画面の流れ

コース作成 → S1 方針確認 → S2 単元の組立て → S3 公開前点検 → 標準の公開操作。保存して後日再開できる通常フォームとし、強制的な長いウィザードにはしない。

### S1 方針確認（作成開始時／既存コースの初回確認時）

```text
このコースをどう学ぶか
○ 教師伴走型：教師の説明・実演・対話と教材を組み合わせる
○ 自学自習型：教師がその場にいなくても教材から進める
どちらも予習・復習、質問、教師による採点を利用できます。
[この方針で作成を始める] [後で確認する]
```

現行の既定値Pathを意思決定済みと見なさない。既存コースには現在の方式を表示し「設計意図は未確認」とする。更新だけでは方式も学生画面も変更しない。「後で確認」は既存の挙動を保持する。新規でのコース保存も妨げず、作成支援を始める時点で明示的な選択を要求する。

### S2 単元の組立て（作成者画面）

```text
方針：教師伴走型     単元：原資料を変更せずに確認する
1 目標と入口      2 授業と作業      3 確認・質問      4 予習・復習
到達目標  [既存の単元概要を編集]
開始教材  [このコースの活動から選ぶ ▾] [標準の活動を追加]
教師が補う内容  [実演・対話の範囲を記す（作成者用）]
学生への説明    [選択した教材を編集]
[下書きを保存] [点検へ]
```

Pathでは「授業と作業」を「自分で進める手順」とし、教師用補足欄の代わりに「口頭説明なしで進めるか」の確認と教材編集リンクを強調する。方式を変えても記載済みの補足を削除しない。

活動選択肢は活動名・種類・セクションを表示し、同名を区別できる。隠された活動を編集権限のある作成者が選べても、学生向けに公開した扱いにはしない。活動追加後は単元に戻って選択する。初回改修では内容の自動生成・配置変更は行わない。

### S3 公開前点検

```text
設定の点検      要対応 1：復習先の活動が削除されています [選び直す]
内容の確認      未確認 2：自習だけで作業開始できる説明／誤答時の解説
学生からの確認  未実施：対象学生によるアクセスと行き先の確認
[作成画面へ戻る] [点検結果を保存]
```

機械判定は「問題を検出／検出なし／判定対象外」。内容確認は「未確認／要修正／確認済み／不要（理由必須）」を別々に表示する。総合的な合格率や品質点数にしない。学生表示の確認に教師のアクセス権を代用しない。点検の保存はコースの公開操作ではなく、標準の公開状態を勝手に変更しない。

## 4. 項目定義と正本

「要」は入力を強制してコース利用を停止する意味ではなく、作成支援で準備済みと扱う条件。空欄でも下書き保存可能。

| 項目キー／表示 | 単位・形式 | 必要性・既定値 | 正本／検証 |
| --- | --- | --- | --- |
| learningmode／基本方針 | コース、guided/path | 明示確認が要。既存値を維持 | 既存format option。初回確認後の変更は例外変更として案内 |
| designconfirmed／方針確認 | コース、真偽 | 初期false | 新規メタデータ。値の既定と選択意図を分ける |
| 単元名・目的・前提 | 標準セクション名・概要 | 目的・前提の内容確認が要 | 標準編集に委譲。独自に本文を複製しない |
| startcm／開始教材 | 単元、活動ID1件 | 要、未選択 | 同コースの存在するURL付き活動。公開状態は別判定 |
| workcm／作業先 | 単元、活動ID1件 | 必要な単元のみ | LTI限定にしない。未設定なら作業先ボタンを出さない |
| checkcm／理解確認 | 単元、活動ID1件 | 活動指定または教材内確認の方針が要 | 標準小テスト等。問題本文の妥当性は人が確認 |
| checkpolicy／確認方法 | 単元、活動／教材内／教師との確認 | 未選択 | Pathの「教師との確認」は即時介入なしの代替手順を要確認 |
| submitcm／最終提出先 | 単元、課題ID1件 | 提出がある場合 | 題材では既存の2ファイル課題。期限・ファイル数は課題設定で管理 |
| submissionpolicy／提出方針 | 単元、この単元で提出／後続で提出／提出なし | 未選択 | 後続で提出も提出先を指定。提出なしを未設定と区別 |
| prepcm／予習先 | 単元、活動ID1件 | 任意 | ない場合は予習ボタンを出さない。独立した方式にしない |
| reviewcm／復習先 | 単元、活動ID1件 | 要、開始教材の再利用可 | 既存解説を再利用。追加教材の作成を強制しない |
| helpcm／質問先 | 単元、活動ID1件 | 下記方針に応じる | forumに限定しない。同コースの案内Pageも可 |
| helppolicy／支援方針 | 単元、質問受付あり／教材内支援のみ | 未選択 | 両方式共通。「あり」なら質問先を要。応答時間の説明はリンク先の正本に置く |
| teachernote／教師が補う内容 | 単元、プレーンテキスト最大2000文字 | Guidedで内容確認が要 | 作成者用。学生に表示しない。個人情報を書かせる用途にしない |
| 内容確認チェック群 | 単元、列挙値＋不要理由最大500文字 | 全て未確認 | 開始説明・順序・誤答時・終了条件・予復習・質問方針の6件 |

複数の説明への戻り分岐は復習先教材の本文にまとめる。初回は独自の分岐エディタを作らない。学習順序は標準のセクション・活動順が正本。「開始教材」は案内入口であり、既存の「最初の未完了」と別表示する。

## 5. 学生画面と状態

各単元の標準活動一覧の前に、設定済みの案内だけを表示する。コース全体の既存概要も維持し、単元未設定なら従来表示に戻る。Guidedの「本時」は日付から自動決定せず、教材に作成者が書いた授業の区切りを参照する。

```text
原資料を変更せずに確認する
[学習の入口] [作業を開く] [確認する]
予習：[列と目的]   復習：[原値を保持する理由と例]   質問：[質問方法]
提出：この単元では提出せず、第2段階の後に2ファイルを提出 [最終課題]
```

- 再訪・完了後も同じ復習入口を表示する。クリックで完了や評点を書き換えない。
- 教材を読んだ印、小テスト結果、提出、講評の閲覧を合算して達成率にしない。
- 未公開・制限中の活動は、学生のアクセス判定に従いリンクを出さない。非開示の活動名・制限理由を独自に明かさない。入口が使えない場合は一般的な案内と許可された活動一覧を残す。
- 質問受付なしなら「質問受付あり」と誤表示しない。教材内支援のみの方針を学生に明示する。
- 教師の未確認メモや点検状態を学生画面に混在させない。
- キーボードで標準順に操作できるフォーム、ラベル・エラーの関連付け、狭い画面での縦配置を採用する。方式の違いを色だけで表さない。

## 6. 保存・権限・変更時の設計

初回の保存方式案は既存のcourse/section format optionsを用い、独自の進捗テーブルは追加しない。列挙値・ID・短文は個別optionにし、巨大なJSONに活動IDを埋め込まない。実装着手時に対象Moodleのセクションoption・バックアップフックを確認し、復元時のID対応を実証してから確定する。

- 編集はコース文脈の `moodle/course:update` を前提に、標準教材の編集には当該活動の権限も要求。閲覧のみの教師には保存を許可しない。サーバーで毎回確認する。
- 保存はPOST・sesskey検証、同コース参照・列挙値・長さ検証を行う。短文はエスケープして出力する。学生のリクエストで設計設定を更新しない。
- 保存内容は単元の共有設計。確認者名・独自の学習者履歴は初回は保存しない。Privacy APIの既存の説明は、新たな自由記述と実保存内容を点検して更新する。
- 教材変更後は点検を再実施する。確認時の対象設定・教材更新情報の指紋を保持し、差を検出したら「再確認が必要」。検出対象外の外部教材変更までは保証せず、公開前の読み直しを要求する。
- 同時編集は読込時リビジョンとの比較で競合を通知し、後勝ちで黙って上書きしない。
- 活動削除・移動は参照無効として作成者に表示。学生側ではリンクを抑制する。復元・複製は活動IDとセクションIDを復元先に対応づけ、対応しない参照を旧コースへ向けない。点検状態は未確認に戻す。
- 更新のみでは既存方式・活動順・学習記録を変更しない。新項目未設定なら従来表示を保持する。
- Topicsへ変更すると新しい案内表示はなくなる。本文・課題・学習記録は標準側に残す。独自optionが往復で保持される保証は実機確認まで行わず、作成支援設定も含むバックアップで保全する。
- 例外的方式変更は両方向で補足の不足を案内してから適用／取消。活動や成績の自動変換はしない。詳細な変更支援は後続段階とし、通常の作成支援を優先する。

## 7. 比較評価と最初の改修範囲

同じ小単元・到達目標・素材を使い、標準Topicsと本設計の両方で作成する。操作順による学習効果を考慮し、担当者間で実施順を入れ替える。初期の開発者試験と、実際の教材作成者・学生による観察を別記録にする。

| 判断・課題 | Topicsで作成者が行うこと | 本設計で支援すること | 測定するもの |
| --- | --- | --- | --- |
| 教師の支援範囲 | 自分で方針を決め本文に反映 | 最初の選択と方式別確認項目 | 迷い、調べ物、口頭補足 |
| 導入・確認・質問・復習の配置 | 活動とリンクを自分で整理 | 役割ごとに既存活動を選択 | 所要時間、重複入力、リンク修正 |
| 自習の誤答対応 | 説明と戻り先を自分で点検 | 解説と再挑戦の内容確認を提示 | 見落とし、手戻り |
| 提出後の復習 | 完了・提出・再閲覧を整理 | 状態を分け、復習入口を保持 | 学生の行き先選択、誤解、補足回数 |

観察票：方式／比較対象／Moodle経験／作成時間／迷った判断／追加説明／重複入力／修正回数／学生が最初に選んだ行き先／達成・未達／理由。数値は未測定。記入欄が増えた負担も評価し、使わない項目は削減する。

最初の実装は **S1の意図確認、S2の既存活動への対応付け、S3の設定点検と人の確認の分離、学生の予習・復習・質問入口** とする。教材自動生成、独自採点、最終閲覧位置追跡、誤答別の自動分岐は含めない。

実装前ゲート：保存API・ID復元方式・内容変更検知範囲を短い技術検証で確定する。実装後ゲート：LD-01〜08/10と棚卸しR01〜R09を確認し、日英・キーボード・小画面・権限を試験する。例外変更のLD-09は後続の独立した終了条件として残す。申請済み版の品質・実装完了とは混同しない。
