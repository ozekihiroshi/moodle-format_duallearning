# 作り始められることを中心にした作成支援仕様

2026-09-18。ユーザーとの方針確認を反映。本書は、作成操作について旧詳細設計のS1〜S3・項目表・実装順より優先する。データ保全、標準機能の優先、二方式と予習・復習の基本方針は維持する。

## 1. 解決する問題

教師がオンライン教材の価値を理解していても、教材づくりの判断や操作の多さが実施の障壁になる。学生の迷いを減らすだけでなく、教師が教材を作り始め、学生が学べる形に仕上げられることを製品の中心に置く。

CanvasやGoogleの教師向けツールの例は、作成者が使いやすい道具を選ぶという設計上の示唆として扱う。市場動向の因果関係を本製品の効果の証拠とはせず、作成者の負担を減らす要求を明確にする。ボツワナでの普及活動で経験された教材づくりの壁を、解決対象として重視する。

**説明書を先に読まず、画面を見て最初の単元を作り始められること。教師は内容を考え、システムの都合に合わせた設計表を埋めない。**

## 2. 必須の設計原則

| ID | 原則 | 採否の基準 |
| --- | --- | --- |
| SA-01 | 空欄の設計表から始めない | 学習方式に沿う編集可能な骨組みと短い例がある。例は完成教材と偽らない |
| SA-02 | 主操作を少数にする | 最初の単元は題名と学生向け本文から作成可能。質問票や設定チェックリストの完遂を要求しない |
| SA-03 | 学生が読むものを直接作る | 本文の正本は標準教材または単元概要。一つの説明を支援画面と教材へ二重入力させない |
| SA-04 | 教育上の行動で案内する | 「説明を書く」「練習を置く」「提出を受ける」を入口にし、詳細なMoodle設定は必要時に示す |
| SA-05 | 問題のある場所で直せる | 自動で分かる不備は該当箇所と修正操作を示す。未確認を合格と扱わないが、全項目の自己申告を常用させない |
| SA-06 | 予習・復習を自然に残す | 両方式の骨組みに含め、不要なら削除できる。方式変更や別教材の一式作成を要求しない |
| SA-07 | 作成途中の失敗を避ける | ひな型は非表示の下書き。取消で何も作らず、既存教材・提出・成績を変更しない |
| SA-08 | 追加の負担も測る | 素のTopicsより操作や迷いが増える場合は追加機能を見直す。機能数では採用を決めない |

少ない操作数だけを追わず、未完成の公開や不適切な採点条件を防ぐ。教材の専門的判断を教師から取り上げず、道具の使い方の判断を減らす。

## 3. 目標とする作成体験

1. コース作成時に教師伴走型か自学自習型を選ぶ。短い説明で違いが分かるようにする。
2. 「ひな型から単元を作る」を押す。方式に合う骨組みが最初から入っている。
3. 題名を付け、例文を自分の内容へ書き換える。その本文が学生に見える説明になる。
4. 必要な位置から説明・練習・提出を加える。教材を持っている場合は再利用する。
5. 作成途中は非表示で保存。学生からの見え方を確認し、準備できたら公開する。

ひな型は「目標／始める前／授業で取り組むこと又は自分で進める順序／確認と次の行動／困ったとき／復習」。これは6個の必須入力欄ではなく、自由に編集・削除できる一つの本文とする。空の課題や小テストは自動作成しない。

一般例は説明の書き方を示すために使う。教科への適合は教師が判断する。自動的に内容を生成して完成と表示しない。

## 4. 今回の実装単位

最初の改修は、既存のコース方式を参照する編集者用入口、日英の本文ひな型、題名＋本文フォーム、標準の非表示セクション作成。本文は通常の単元編集で引き続き編集できる。専用の設計メタデータはまだ追加しない。

これにより独自活動IDの復元や設計表の保存を先に作る必要をなくす。作成した内容の保管・移動・バックアップは標準セクションの仕組みに委ねる。ただし実機復元を確認するまでは復元試験済みとは言わない。

初回には含めないもの：新規コースの方式選択UIの再設計、本文内からの簡易活動追加、学生プレビューの改善、その場での不足検出、例外的方式変更支援。これらを未実装として残し、現行設定が作成意図を確認済みであるとも扱わない。

現行の活動追加操作を使う段階は、目指す使いやすさの完成ではない。最初の動く土台として評価し、次の改修で「説明を書く／練習を置く／提出を受ける」を実際の追加操作につなぐ。

## 5. 実装と評価の順序

1. 本文ひな型から下書きを作れる状態を実装し、権限・非表示・既存データ保全を検証する。
2. 教師役が説明書なしで「最初の単元を作る」操作を試す。どこで迷ったか、例が役立ったかを記録する。
3. 標準Topicsで同じ内容を作った場合と比較する。手数、時間、調べ物、口頭補足、手戻り、不要な記入を観察する。
4. 次の活動追加支援は観察された迷いを解消するものから加える。

採用条件：主要操作が見つかる、例を自分の教材に置き換えられる、学生向け本文を重複入力しない、下書きを公開済みと誤解しない。所要時間短縮や学習効果は未測定のまま主張しない。開発者の動作確認を教師による使いやすさ評価の代わりにしない。

## 6. 旧詳細設計の扱い

`AUTHORING_DESIGN.ja.md` の教材例、責任分界、権限・保全条件は設計資料として残す。S1〜S3の長い通常フロー、項目ごとの登録表、6件の内容確認を毎回保存する方式は採用しない。活動の役割付け・独自option・確認状態保存は、必要性が観察されるまで保留する。

LD-01〜10は維持するが、それを独立した必須入力欄へ一対一で変換しない。特にLD-03の人による確認は、読んで判断できる作業とすることを優先し、チェックボックスの数で品質を保証しない。

## 7. 第2段階の実装範囲（2026-09-18）

SA-04に対応し、単元ごとの説明・練習・提出の入口を標準活動作成フォームにつないだ。保存直後と既存単元の両方から再開できる。本文内の任意位置への挿入や標準フォーム自体の簡略化は含まない。詳細と未確認部分は [単元の活動追加入口の確認記録](UNIT_ACTIONS_RESULTS.ja.md) を参照。第4節の「次の改修」の入口部分は実装済みになったが、教師による使いやすさ評価は引き続き未実施とする。

## 8. 再編集と戻り道（2026-09-18）

作成支援に既存教材の一覧と標準編集リンクを追加した。教材・単元・標準編集画面の上部から所属単元の作成支援に戻れる。入力は戻りリンクで保存せず、標準フォームで保存する。教師向けの操作だけを追加し、独自の入力項目は増やさない。詳細は [再編集と戻り道の検証記録](AUTHORING_RETURN_RESULTS.ja.md) を参照。

## 9. 初心者と熟練者が同じ画面で作業できること（2026-09-18）

- 主操作は説明を開かずに実行できる。説明の閲覧を作業の前提にしない。
- 操作場所とラベルを共通にし、初心者／熟練者のモード選択や習熟度の自己申告を要求しない。
- 手順や設定場所の補足は、その操作の近くで必要なときだけ展開する。自動ポップアップや繰り返しの案内を増やさない。
- 公開状態、エラー、未保存入力を失う可能性など、判断に不可欠な情報は折りたたまない。
- 説明を隠すこと自体を使いやすさの達成としない。初回に主操作とヒントを発見できるか、再訪時に説明を飛ばして作業できるかを両方評価する。

今回の実装：単元作成支援の活動別説明と保存・戻り方の説明を、初期状態では閉じた「ヒント」に変更。既存教材の編集と新規追加の操作は常時表示。日英対応。ブラウザー標準のdetails/summaryを利用し、新しいJavaScript、保存設定、データ項目は追加していない。開閉状態の永続保存や標準活動フォーム内部の簡略化は今回含まない。

確認：PHP構文と差分チェック、日本語画面で初期折りたたみ・クリックで展開・Enterで閉じる操作を確認。実際の教師による初回／反復作業の比較は未実施。
