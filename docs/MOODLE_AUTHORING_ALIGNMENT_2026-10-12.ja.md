# Moodle標準の教材作成導線との整合性監査

[English](MOODLE_AUTHORING_ALIGNMENT_2026-10-12.md) | 日本語

2026-10-12。今回は監査のみ。この確認で製品の動作を追加変更していない。

## 結論

**標準の教材作成機能は残っているが、作成支援の経路は教材選択を飛ばしている。** コース画面の編集モードではMoodle標準の活動選択画面を利用できる。一方、専用の単元作成支援には固定した種類への直接リンクしかなく、その場から標準の選択画面へ進む入口がない。標準フォームを使っているだけでは、支援経路に入った利用者にも標準の導線が保たれているとは言えない。

参加者は単元紹介文とページ本文の違いに迷い、説明を受けてページを保存した後、PDF・Markdown・他のツールをどこで選ぶのか質問した。これは支援ありでの完了と選択肢の見つけにくさの観察である。標準Moodleや全利用者に同じ再設計が必要だという証拠ではない。

- 独立した評価環境の標準Topicsコース2とDual Learning開発者用コース29を比較。参加者コースは変更していない。コース28は開発者教師に登録権限がなかったため、登録を変更せず既存のTopics比較コースを使った。
- Formatの `codex/authoring-entry-recovery-20261012`、HEAD `ec81e72` と、評価環境へ反映済み・未コミットのAdd a page名称・説明修正が対象。公開版そのものの監査ではない。
- `format.php`、`author.php`、`unit.php`、`classes/local/unit_actions.php`、`classes/local/unit_starter.php`、`classes/form/unit_starter.php` と既存仕様を確認した。
- Topicsで Edit mode → 対象単元のInsert content → Activity or resource → 選択画面 → Resources → File → Addを操作。New File、ファイル選択、標準保存ボタンまで確認し、アップロード・保存せずCancelした。検索、分類、説明、お気に入りが存在し、既存のお気に入り設定は変更していない。
- Dual Learningのコース画面でも、同じ追加経路から対象単元を維持した標準選択画面を開けた。閉じて開発者セッションの編集モードをオフに戻した。教材・単元は新規作成していない。
- LessonMarkはこの環境に未導入。導入時の追加プラグイン発見性は未検証。Fileフォームに到達したことはPDFアップロードや学生の閲覧成功を意味しない。

| 公開状態 | セクション・活動の公開範囲とアクセス規則 | 非公開セクションを下書きと呼んでいる。独立した個人用下書き保存機能ではなく、自動公開も行わない |

旧称Add an explanationは、教材種別より目的を示すため混同を強めた。Add a pageへの変更は対応を明確にするが、それだけでは他の選択肢が見えるようにならない。

## 次の改修に引き継ぐ判断

1. 現在の単元から標準の教材選択へ到達できるようにする。利用者に別経路を発見させない。対象単元と権限を維持する。一般的な追加入口を検証したうえで、直接追加の短縮操作を残す価値を判断する。
2. 一部の教材一覧を独自に作り直さず、標準の選択機能を再利用する。導入・許可された活動、検索、説明、分類、お気に入り、管理者設定を尊重する。Pageの作成URLに直接飛ぶだけではこの条件を満たさない。
3. 標準のコース編集を維持する。ファイルなどを追加する前に、新規単元、紹介文、作成ウィザード、初心者／熟練者モードを必須にしない。
4. 標準の教材名を見えるようにする。用途の説明は補助に使い、教師に代わって教材種別を暗黙に決めない。
5. 標準フォームと保存動作を維持する。一人の迷いからフォーム全体の簡略化へ飛躍しない。

`SIMPLE_AUTHORING_SPEC.ja.md` のSA-04と第2段階の実装方針は、目的別の直接リンクを推奨している。この意図を共通原則改訂5と整合させる必要がある。支援は選択を分かりやすくするものであり、限られた一覧がMoodleの機能の全てだと見せてはならない。本監査はこの衝突を記録する。代替導線はまだ実装・利用者検証していない。

## 追記：標準教材選択への変更

単元画面からMoodle標準の活動・リソース選択を開く形へ変更した。Page／LessonMark／小テスト／課題の固定した直接リンクは削除した。文章・画像はPage、既存PDFはFile、WebリンクはURLという短い説明を添えるが、教師に代わって教材の種類を決めない。

標準のセクション情報、ボタンテンプレート、選択画面のJavaScript、作成フォームを再利用する。別画面である単元画面には、コース編集画面専用のサブセクション挿入等を混在させない。通常のコース編集導線は維持する。単元画面を開くだけで編集モードの設定は変えず、作成フォームの保存前に教材は作らない。

ローカルの開発者点検では、編集モードがオフでも選択画面が開き、Page／File／URLの宛先が同じセクションIDになること、Resourcesカテゴリと既存のお気に入りを利用できることを確認した。390px幅でも選択画面が開いて画面内に収まる。ただしPCでの狭幅点検であり、iPhone実機や支援技術の評価とは区別する。参加者の保存済み紹介文とPageは残っており、参加者の教材は変更していない。

TopicsとDual Learningの双方でPage・PDFを添付したFile・URLを作成するブラウザ回帰テストを追加した。保存先とPDFの保持、追加Pageの取消、非公開単元の学生非表示を確認する。CIの確定結果を下記に記録する。初見・熟練教師それぞれの実評価、iPhone実機のアップロード、スクリーンリーダー、導入済み任意プラグインの発見は別途の受入確認として残る。

## 目的との整合性の再評価 — 標準選択への移行後

**判断は条件付き維持とする。** 単元を構成し、作業を再開し、学生の学習を案内する中核機能を今回の変更で失った証拠はない。教材選択の網羅性と標準操作との整合性は改善した。一方、目的別の作成支援と既知の教材へ直行する短さは一部失われた。「全面的に使いやすくなった」「学習が改善した」とはまだ判定しない。

### 根拠と対象

2026-10-12に `ec81e72`（選択変更前）と `55c1336`（検証済み実装）を比較した。共通開発指針の改訂5、作成UXマイルストーン、単元画面、追加処理、学習方式、学生の概要・ナビゲーション、既存回帰テストを照合した。今回の監査で実行コードは変更しておらず、同一コードで成功したCIを再実行していない。

iPhoneでの追加報告も得られた。参加者はURLの入力、保存・表示、その後の再編集について「ここはOKでした」と報告した。これは参加者の自己報告であり、こちらが操作を直接観察した結果ではない。事前にURLで試すという提案と保存・再編集の確認案内があり、同じ参加者は以前の画面を経験している。初見・無補足での成功や旧版との所要時間比較には数えない。iPhoneでPDFを扱った経験はないとの報告があり、実機PDFアップロードは未実施として残す。

### 失った支援を明示する

旧画面にはPage、任意のLessonMark、小テスト、課題への直接ボタンと個別ヒントがあった。種類が決まっている場合、標準フォームまでは直接リンク1回だった。現在は追加ボタン→種類を選択→Addの少なくとも3操作で、検索やカテゴリ変更が必要ならさらに増える。これは画面構造の比較であり、実測時間や誤操作率の比較ではない。

小テストの問題・解説作成、課題の提出タイプに関する固有のヒントは、言語ファイルに残っていても単元画面からは表示されなくなった。現在の短い例はPage／File／URLだけである。「理解を確かめたい」「提出物を集めたい」という教育上の目的からQuiz／Assignmentへたどる支援は薄くなっている。LessonMarkの専用入口もなくなり、導入済み任意プラグインとしての発見性は未確認である。これは継続評価すべき代償として記録し、存在しない支援を維持したとは説明しない。

### Dual Learningに残る価値

役割は残っている。標準教材を選んだ前後で、どの単元の作業か、保存した教材はどれか、公開されているか、どこから再編集するか、学生ロール確認からどう戻るかをまとめる。また、学習側では可視性・完了・期限・提出状況を基に活動間の案内を提供する。これらを実現する基礎機能の多くはMoodleにもあり、独自性はそれを学習・作成の文脈にどうまとめるかにある。標準Topicsで教材を追加できることに対する、この追加価値の大きさはまだ比較測定していない。

コードの根拠は `unit.php`、`classes/local/unit_starter.php`、`classes/local/authoring_navigation.php`、`classes/local/student_view.php`、`classes/local/overview.php`、`classes/local/mode/`、`classes/output/ordered_activity_navigation.php`。選択変更で主に変えたのは `unit_actions::build()` の限定一覧と単元画面の追加部分である。その他の上記中核クラス・ナビゲーション・テンプレートには比較区間で差分がなかった。差分がないことだけを無不具合の証明とはせず、既存CIの範囲と合わせて判断した。

完了設定にも注意が必要である。`overview::collect_completion()` は完了追跡が有効な教材を対象とし、`first_incomplete()` がその中から次を選ぶ。教材の保存だけで学習経路が自動完成するわけではない。これは今回導入した制約ではなく、従来からある条件である。Page／PDF／URLの追加テストは保存と非公開を確かめるものであり、この3教材による学習再開までの一巡を証明しない。

### 採否と次の受入確認

現行の標準選択を維持する。確認できた問題を解決するため、まず評価を行い、直ちに独自ボタン・ウィザード・初心者モードを復活させない。

1. 教師に「短い説明を置き、理解を確かめる問題を用意し、提出物を受け取れるようにする」という目的だけを渡す。クリック先や教材名は先に教えず、種類を選べるか、同じ単元へ戻れるか、公開状態を説明できるかを見る。単元概要とPageの混同、Quiz／Assignmentを探す迷い、不要な教材の作成を記録する。
2. 新たな初見参加者とMoodle熟練者を分け、標準Topicsと同じ教材・権限・端末で比較する。試行順による慣れを記録し、停止、補足、手戻り、操作数・時間を記録する。今回の継続参加者を再び完全な初見と扱わない。
3. 教師主導型・自律学習型それぞれで、公開・利用制限・完了条件を意図的に設定した検証用教材を学生として読む。リンクから戻り、完了・取消後に次の案内が意図どおりか、iPhoneを優先して確認する。参加者の下書きを検証のために勝手に公開しない。
4. 目的から種類を選ぶ箇所に繰り返し迷いが出る場合は、標準選択の前後に短い用途説明を補う最小案を試す。固定された部分的な一覧への逆戻りを最初の解決策としない。熟練者に新たな必須操作を増やさない。

結論の範囲を限定する。**中核機能の維持と教材選択経路の改善には根拠がある。目的別支援には明確な減少があり、作成負荷全体・学生の学び・熟練者への効果は継続評価する。**
