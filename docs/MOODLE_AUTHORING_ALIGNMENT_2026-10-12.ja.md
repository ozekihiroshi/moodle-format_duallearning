# Moodle標準の教材作成導線との整合性監査

[English](MOODLE_AUTHORING_ALIGNMENT_2026-10-12.md) | 日本語

2026-10-12。今回は監査のみ。この確認で製品の動作を追加変更していない。

## 結論

**標準の教材作成機能は残っているが、作成支援の経路は教材選択を飛ばしている。** コース画面の編集モードではMoodle標準の活動選択画面を利用できる。一方、専用の単元作成支援には固定した種類への直接リンクしかなく、その場から標準の選択画面へ進む入口がない。標準フォームを使っているだけでは、支援経路に入った利用者にも標準の導線が保たれているとは言えない。

参加者は単元紹介文とページ本文の違いに迷い、説明を受けてページを保存した後、PDF・Markdown・他のツールをどこで選ぶのか質問した。これは支援ありでの完了と選択肢の見つけにくさの観察である。標準Moodleや全利用者に同じ再設計が必要だという証拠ではない。

## 確認方法と範囲

- Moodle 5.2.4（Build 20261005）、Boost、編集権限のある教師Comparison Teacher。PC Chromeでの開発者操作であり、iPhoneや熟練教師の利用評価ではない。
- 独立した評価環境の標準Topicsコース2とDual Learning開発者用コース29を比較。参加者コースは変更していない。コース28は開発者教師に登録権限がなかったため、登録を変更せず既存のTopics比較コースを使った。
- Formatの `codex/authoring-entry-recovery-20261012`、HEAD `ec81e72` と、評価環境へ反映済み・未コミットのAdd a page名称・説明修正が対象。公開版そのものの監査ではない。
- `format.php`、`author.php`、`unit.php`、`classes/local/unit_actions.php`、`classes/local/unit_starter.php`、`classes/form/unit_starter.php` と既存仕様を確認した。
- Topicsで Edit mode → 対象単元のInsert content → Activity or resource → 選択画面 → Resources → File → Addを操作。New File、ファイル選択、標準保存ボタンまで確認し、アップロード・保存せずCancelした。検索、分類、説明、お気に入りが存在し、既存のお気に入り設定は変更していない。
- Dual Learningのコース画面でも、同じ追加経路から対象単元を維持した標準選択画面を開けた。閉じて開発者セッションの編集モードをオフに戻した。教材・単元は新規作成していない。
- LessonMarkはこの環境に未導入。導入時の追加プラグイン発見性は未検証。Fileフォームに到達したことはPDFアップロードや学生の閲覧成功を意味しない。

## 比較

| 段階 | Moodle標準 | 作成支援の現状と判断 |
| --- | --- | --- |
| 置く場所を選ぶ | 既存セクションで作業し、必要なときだけセクションを追加 | 単元一覧・作成フォームを別に提供。単元は標準セクションに対応する。教材追加のたびに新規単元や紹介文を必須にしてはならない |
| 教材・ツールを選ぶ | 利用可能な種類を、説明・検索・分類・お気に入りとともに選ぶ | `unit_actions::build()` はPage・LessonMark・Quiz・Assignmentを固定列挙し、利用可否で絞る。File・URL・Book・Folder・Forum・H5P・外部ツールの入口はここにない |
| 内容を入力する | 種類を選んだ後、その標準フォームへ進む | 標準フォームは再利用している。Pageを選んだ後の直行は有効な短縮操作だが、一般的な教材選択の代わりではない |
| 紹介文を保存する | セクション概要と教材本文は役割が異なる | ひな形の保存先はセクション概要。専用概要エディタは `maxfiles=0` で、標準の教材・ファイル作成の代用ではない |
| 保存・復帰 | 標準の保存してコースへ戻る／保存して表示／取消 | 維持されており、参加者は案内後に利用できた。単元への戻りリンクの価値は仮説であり、自力で使いやすい証明ではない |
| 公開状態 | セクション・活動の公開範囲とアクセス規則 | 非公開セクションを下書きと呼んでいる。独立した個人用下書き保存機能ではなく、自動公開も行わない |

旧称Add an explanationは、教材種別より目的を示すため混同を強めた。Add a pageへの変更は対応を明確にするが、それだけでは他の選択肢が見えるようにならない。

## 次の改修に引き継ぐ判断

1. 現在の単元から標準の教材選択へ到達できるようにする。利用者に別経路を発見させない。対象単元と権限を維持する。一般的な追加入口を検証したうえで、直接追加の短縮操作を残す価値を判断する。
2. 一部の教材一覧を独自に作り直さず、標準の選択機能を再利用する。導入・許可された活動、検索、説明、分類、お気に入り、管理者設定を尊重する。Pageの作成URLに直接飛ぶだけではこの条件を満たさない。
3. 標準のコース編集を維持する。ファイルなどを追加する前に、新規単元、紹介文、作成ウィザード、初心者／熟練者モードを必須にしない。
4. 標準の教材名を見えるようにする。用途の説明は補助に使い、教師に代わって教材種別を暗黙に決めない。
5. 標準フォームと保存動作を維持する。一人の迷いからフォーム全体の簡略化へ飛躍しない。

`SIMPLE_AUTHORING_SPEC.ja.md` のSA-04と第2段階の実装方針は、目的別の直接リンクを推奨している。この意図を共通原則改訂5と整合させる必要がある。支援は選択を分かりやすくするものであり、限られた一覧がMoodleの機能の全てだと見せてはならない。本監査はこの衝突を記録する。代替導線はまだ実装・利用者検証していない。

## 次の実装の受入確認

TopicsとDual Learningで同じ作業を比べる。Page作成、既存PDFのFile追加、URL追加、導入済み任意活動の発見を対象とする。追加先単元の維持、取消で新規活動が残らないこと、標準設定・保存・復帰の利用を確認する。非公開／公開単元、活動の制限、学生アクセスも確認する。LessonMarkなしの独立動作と、導入・許可された場合を分ける。独立動作の検証を通すためだけにLessonMarkを導入しない。

初見教師と熟練教師を分けて観察し、操作数だけでなく支援・誤った経路・覚え直しの負担を記録する。iPhoneのタップ、キーボード、支援技術も確認する。PDFアップロード、モバイルでのタップ、任意プラグイン発見性、熟練教師による評価は未完了であり、以前のCIで解決済みとはしない。以前の別画面への誤遷移は原因未確定なので、推測でCSSを変更しない。
