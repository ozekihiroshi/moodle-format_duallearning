# 教材作成の一巡比較

[English](AUTHORING_COMPARISON_2026-10-11.md) | 日本語

2026-10-11。[設計・実装監査](DESIGN_IMPLEMENTATION_AUDIT_2026-10-11.ja.md)の追跡検証。

## 結果

**4つの組合せで一巡できた。** 編集権限を持つ教師がPage教材を作成し、学生ロールで確認し、編集に戻って題名を修正した。同じ教材IDが維持され、本文と非表示状態も保持された。独立した履修学生でも、下書きが見えず、教材URLへの直接アクセスもできないことを確認した。

| コースフォーマット | テーマ | 作成・学生ロール確認・復帰・修正 | 独立した学生 |
| --- | --- | --- | --- |
| Topics | Boost | 成功 | 非表示の下書きにアクセス不可 |
| Dual Learning | Boost | 成功 | 非表示の下書きにアクセス不可 |
| Topics | Dual Learning | 成功 | 非表示の下書きにアクセス不可 |
| Dual Learning | Dual Learning | 成功 | 非表示の下書きにアクセス不可 |

これは導線が機能することの確認である。初見の教師の迷いが減ったことや、学習効果が改善したことの実証ではない。

## 環境の統一

比較専用環境 `http://localhost:8098` を作成した。Moodle 5.2.2（Build: 20260810）、PHP 8.3.33、Format 0.1.0-alpha10（2026093000）、Theme 0.1.0-alpha7（2026101000）を使用した。DB登録版とマウントしたソースの版は一致している。保管済みリリースZIPを展開し、ハッシュを過去の配備記録と照合した。LessonMarkはインストールしていない。

コンテナ・DB・データ領域・ネットワークを分離した。既存の8083環境は更新していない。標準との比較は同じ基盤上のTopicsとBoostを指し、それ以外の追加プラグインが一切ない構成という意味ではない。

4コースには同等の空の非表示セクションを用意した。コース作成とセクション作成は今回の対象外である。操作には管理者ではなく編集教師を使い、独立した架空の履修学生でも権限を確認した。

## 実際の導線

**Dual Learningはユニットへの戻り先が明確だった。** 編集モードで「Continue building a unit」から下書きを選択し、「Add an explanation」で教材を追加した。LessonMarkがない状態では、説明・練習問題・提出物という3つの追加操作が表示された。説明の追加先はMoodle標準のPageフォームだった。

保存後は「Back to unit authoring」で同じユニットに戻れた。ユニットと教材の非表示状態がそれぞれ表示された。「Check with role: Student」で学生表示を確認し、復帰操作で同じユニットに戻った。既存教材の編集リンクから標準フォームを開き、題名を修正できた。

**Topicsは汎用の活動選択を使った。** 下書きセクションの「Insert content」→「Activity or resource」で選択画面を開き、Pageを選んでAddを押すと同じ標準フォームに進んだ。学生ロールへの切替と復帰はユーザーメニューから行い、教材を開き直してSettingsから修正した。

Formatには作業中のユニットへ直接戻る導線がある。一方、教材フォーム自体の設定量は標準Moodleと共通だった。両テーマで一巡でき、今回の操作ではDual Learningテーマによって新たな作成操作が増えることはなかった。

## 発見と次の判断

1. **同じユニットへの復帰を維持する。** 復帰して既存教材を修正する流れは機能した。初見の教師に評価してもらう価値があるが、容易さの実証はまだない。
2. **空の学生画面を整理する。** 非表示教材しかない場合も、Dual Learningには「確認・学習継続」趣旨の見出しだけが残った。概要欄を省くか、現状に合う空状態の説明にする案を検討する。教材へのアクセス制御は維持されており、表示上の課題である。
3. **最初の入口を評価する。** 編集モードとユニット選択が必要だった。初見で発見できるかは未確認であり、ボタンや概念を追加する前に入口を検証する。
4. **標準の操作経路を維持する。** 高度な設定は標準フォームで利用できる。フォームを重複実装するより、必要に応じて受け渡しの導線を整理する。

機能追加より、この範囲の表示と移動を優先して検討する。教師主導型と自律学習型の適合性は、別々のシナリオで確かめる必要がある。

## 証拠と限界

ローカルの検証資料は `moodle-rescue/build/dual-learning-audit-20261011/comparison/` にある。`baseline.json` は版と初期状態、`after.json` は最終教材ID・本文・表示状態・利用者別アクセス、`artifacts.json` はZIPハッシュを記録している。`fixture.php` は準備、`verify.php` は読み取り検証用である。`runtime.env` にローカル認証情報があるため、ディレクトリ全体を公開してはならない。

最終状態は各コースにPageが1件ずつで、コースID/教材IDは2/2、3/1、4/4、5/3だった。題名はすべて「Checking a data table — revised」となり、データ表を確認する同じ本文が保持された。セクションと教材の表示値はともに0で、教師はアクセス可能、独立学生は不可だった。学生の各コース画面にも下書きは表示されなかった。教材URLへの直接アクセスはコースへ戻り、最後に確認した要求では「Sorry, this activity is currently hidden」が表示された。

開発側による操作再現である。Format/Boostの一巡にはアプリ内ブラウザ、ほかの3つにはChromeを使用し、表示幅も異なる。アプリ内ブラウザでは標準の活動選択が安定して開かず、Chromeでは開いたため、製品の不具合として扱わなかった。時間短縮やクリック数の優位性は主張しない。Moodle初回ツアーによる中断もあった。

今回は未公開の下書きが見えないことを確認した。公開教材を学生が理解できるかの評価ではない。初見の参加者、公開教材の読み進め方、モバイル、教師主導型の進行、条件付き利用、完了条件の境界、長いユニット、サブセクションは未検証である。ロール切替だけで個々の学生のアクセス確認を代替してはならない。

## 最初の改修：空の概要欄

完了対象・リンク・課題のすべてが空の場合だけ、概要カードを省く候補修正を加えた。標準の教材一覧は残る。完了済みの対象がある場合も完了表示を維持する。空欄を説明するためだけの案内や操作は追加しない。

BoostとDual Learningテーマのコースで、非表示の下書き・完了追跡なしの表示Page・未完了Page・完了済みPageの計8件の描画検証に合格した。Chromeでも、非表示教材だけの学生向けBoost画面から空の見出しが消え、標準セクション一覧が残ることを確認した。一時的なDB変更はロールバックし、共有キャッシュも消去した。4コースの元の記録がすべて保存済み状態と一致することを照合した。PHP構文と差分の空白検査にも合格した。既存のPHPUnitテストに回帰用の検証を追加したが、この比較用イメージにはPHPUnit実行環境がないため、全スイートとリモートCIは未実行である。

8098は現在 `compose.candidate.yml` の候補ソースを使用している。元のリリース展開物と `compose.override.yml` は保持しており、比較基準へ戻せる。リリース版番号の変更と本番反映は行っていない。
