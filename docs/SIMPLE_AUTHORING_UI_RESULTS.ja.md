# 初回作成支援：自動検査・画面操作の結果

2026-09-18。対象コード `25f1fe6`、開発ブランチ `codex/simple-authoring`。申請済みリリースの差替えではなく、ローカル検証環境への適用。

## 自動検査

[GitHub Actions実行結果](https://github.com/ozekihiroshi/moodle-format_duallearning/actions/runs/35288381180) は全ジョブ成功。PHP 8.3・8.4で構文、CodeSniffer、PHPDoc、プラグイン検証、savepoints、PHPUnitを実行。PHPUnitは6テスト・14アサーション。ZIP再現性検査も成功。CI生成物は開発ブランチの検査用で、Marketplaceへ送信していない。

最初のCIでは、ローカルの旧版checkerにはなかった複数行if条件と翻訳キー順序の指摘があった。条件判定を変数に分け、日英キーを整列して解消。最初の失敗を最終結果と混同しない。

## 教師画面での操作

既存の教師アカウントで、今回作った非表示コース32（Guided）・33（Path）を使用。元のコース23・24の教材・提出・成績を操作していない。

| 操作 | 結果 |
| --- | --- |
| 編集モードで入口を探す | コース上部に「ひな型から単元を作る」。通常表示では編集者用入口を出さない設計 |
| Guidedの日本語ひな型 | 授業・実演を含む本文が最初から入る。予習と復習もある |
| キャンセル | 単元を作らず元のコースへ戻る |
| 題名→本文 | Tabキー1回で題名からリッチテキスト本文へ移動できた |
| 本文編集・保存 | 例文を単元の説明へ置き換えて保存。単元295に内容が反映され「学生から秘匿」と表示 |
| 標準の再編集 | 編集メニューから題名を変更。本文と非表示状態を保持 |
| Pathの英語ひな型 | 自分で進む順序と戻り先を含む本文。UI・案内・ボタンが英語 |
| 空の題名で送信 | エラーを題名付近に表示し、題名へフォーカス。修正後に保存できた |
| 保存後の次の操作 | 編集メニューの「設定を編集する」は本文編集と結びつきにくいため、保存通知に「本文を編集する」を追加。単元301で一操作で標準編集へ到達 |
| 単元を表示 | 標準の利用メニューから表示へ変更でき、学生権限による利用可能判定も確認 |

表示確認は実際のブラウザ幅で実施。約555px幅のフォームではラベル・本文が縦配置され、横にはみ出さず表示された。全端末・全幅の試験やキーボードのみでの全行程試験を完了した意味ではない。

学生権限は標準modinfoとサービスで検証した。検証コースへの一時登録をロールバックし、表示単元は利用可能・非表示単元は利用不可・作成サービスは拒否と確認。学生本人のブラウザ操作試験とは区別する。

## バックアップ・復元

今回のコース32→34、33→35へ、利用者履歴なしの標準バックアップを復元。単元名、本文、本文形式、非表示状態、学習方式を照合した。本文はバックアップXMLによってCRLFからLFへ正規化されるため、その差のみを除いて一致を確認。作成済みの旧教材・提出履歴を含む全回帰試験ではない。

## 作りやすさについての判断

**開始の支援として採用可能。ただし教材づくり全体の簡易化は未完成。** これは開発側の操作点検による判断で、教師を対象にした比較実験の結果ではない。

- 題名と本文だけで始められ、説明の構成を空欄から考える必要が減る設計になっている。
- 六つの見出しは一つの本文として自由に削除・編集でき、六つの必須設定項目にはなっていない。
- 反面、現在の例文は長く、教科に合う文章へ書き換える必要がある。ひな型を使えば教材が完成するとは言わない。
- 画像添付・練習・提出活動を加える場面は標準Moodleの操作へ戻る。ここが次の改善対象。
- 再編集への導線は今回一つ改善したが、保存通知は一時的。通常の再訪時は標準メニューを使う。
- 標準Topicsとの所要時間・迷い・手戻り比較、実際の教師による説明書なしの作成観察は未実施。負担軽減率は算出しない。

次は「説明を書く／練習を置く／提出を受ける」から適切な標準操作へ進める支援を、小単元で設計・観察する。入力項目の追加を先に決めない。

## 環境と引継ぎ

適用前のローカルプラグインを `LessonMark/output/duallearning-before-ui-20260918` に退避した。今回の変更はauthor.php、format.php、作成用2クラス、日英文字列。AWSには適用していない。

準備時にrootでキャッシュを更新したためWeb側の書込み権限エラーが発生した。cache/localcacheの所有者をwww-dataへ戻して解消し、以降のCLI検証・キャッシュ更新はwww-dataで実行した。

試験補助スクリプトとCIログは `LessonMark/output` 内に保存。検証コースと復元コースは確認用に保持する。表示試験をした単元295も最後に非表示へ戻し、画面と保存値で確認した。
