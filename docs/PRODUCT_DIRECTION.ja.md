# Dual Learning：中心思想・現在地・次工程

日付：2026-09-18

文書の位置づけ：オーナーとの対話で明確になった設計方針と、次工程の評価案。
中心思想は合意内容の記録であり、下記の機能候補や合格基準案は実装済み機能・確定したリリース予定を意味しない。

## 正式な改修要求仕様

作成時に学習形態を選び、通常は維持して運用すること、両方式の予習・復習を保全すること、方針変更を例外として支援することを、[学習設計・作成支援仕様](LEARNING_DESIGN_SPEC.ja.md)に定めた。以後の改修は同仕様を基準とし、本書の機能候補・順序と異なる場合は同仕様を優先する。

## 1. 中心命題

**教師が担う支援と教材が担う支援の分担を明確にし、その学習形態に合ったコースを作りやすく、学びやすくする。**

教師がその場で説明・問いかけ・進行判断を担う教材と、学習者が主として自分で進める教材では、設計時に必要な判断が異なる。Moodleの豊富な機能を前に、作成者が目的を定めないまま設定の選択を迫られると、構成や案内が曖昧になり、その負担が学習者の迷いへつながる。

Dual Learningは、最初に想定する学習形態を定め、必要な設計判断を整理し、適切な構成・設定・案内へ結び付けることを目指す。モード切替やコース概要表示は、この目的を実現する手段である。

狙いは項目を機械的に隠すことではない。目的に合う選択肢と判断順序を提示し、必要な場合はMoodle標準の詳細設定に進めるようにする。

## 2. 原仕様との関係と維持する決定

参照した初期文書：`moodle-dual-learning-project-plan.md`（2026-09-13）。

- 4.1：増やすのではなく、迷いを減らす。
- 6.1：教師が口頭で補う内容と、教材に残す内容を区別する。
- 6.2：口頭補足がなくても進められ、失敗時の戻り先がある。

今回の明確化はこの思想を維持し、教材作成者の負担を独立した評価対象として具体化する。初期文書のダウンロード原本は歴史資料として変更しない。

後続の正式判断である「二方式を切り替える単一の `format_duallearning`」「独立した `theme_duallearning`」を維持する。初期案の二つの別フォーマットへ戻さない。公開プラグインが成果物であり、サイトやモデルコースは検証手段である。

## 3. 二方式の意味

| 設計対象 | 教師伴走型 | 自学自習型 |
| --- | --- | --- |
| 導入 | 教師の導入と教材の役割を決める | 目的・前提・開始手順を教材内に用意する |
| 説明 | 実演・対話で補う部分と残す資料を決める | 単独で読める説明・例・補足を用意する |
| 進行 | 教師が調整する区切りと活動を定める | 順序と次へ進む条件を示す |
| 理解確認 | 問いかけ・観察・提出等を組み合わせる | 自己確認・小テスト・課題と結果の読み方を用意する |
| つまずき | 教師の介入・質問経路を用意する | ヒント・戻り先・再挑戦・質問経路を用意する |
| 終了 | 振り返り・講評・次回までの作業を明示する | 到達条件と未達時・完了後の行動を明示する |

自学自習型は「支援者が一切いない」という意味ではない。非同期の質問や採点があってよい。教師伴走型でも自習・復習はあり得る。作成者と担当教師が別人でも成立させる。

同じ教材を再利用できることと、説明を補わずに学習形態を変更できることは異なる。切替時には、教師の口頭説明・介入に依存している箇所の点検が必要になる。

## 4. 現在の実装と不足

基準：公開済みソースの `0.1.0-alpha1`。申請・審査の状況は本書では更新しない。

| 領域 | 実装済み | まだ提供していない支援 |
| --- | --- | --- |
| 学習形態の選択 | コース単位のLearning mode設定 | 目的に沿った作成手順・構成提案 |
| 学生への案内 | Topics上部の概要、利用可能な未完了活動へのリンク | 誤答時の戻り先・未完了理由の統合案内 |
| 作成作業 | Moodle標準の編集・活動設定を利用 | 設定漏れ検出、作成チェック、設定支援 |
| 提出・評価 | 課題の提出状態・評点公開状態と標準画面へのリンク | 小テストの受験・合否・再受験状態の専用要約 |
| 質問先 | Guidedでアクセス可能なフォーラムを列挙 | モードと独立した質問先指定 |
| 方式の移行 | モード変更でも学習記録を保持 | 教材の自習適性を点検する移行支援 |

現状は学生向け表示の基盤であり、作成負担の軽減まで実証した完成形ではない。既存のCI・操作試験の合格を、教育効果や作成容易性の実証に読み替えない。

## 5. 責任分界

- 教材：目標、説明、例、ヒント、解説、振り返り。
- Course format：学習形態に沿う構成・作成支援・導線・標準状態の要約。
- Moodle標準：小テスト、課題、提出、採点、完了、利用制限、権限、カレンダー。
- テーマ：可読性、余白、共通の視覚表現。
- LessonMark：Markdown教材の作成・表示・再利用。必須依存にしない。

合否判定や提出記録を独自に複製しない。作成支援を実装する場合も、既存教材・完了条件・成績を無断で上書きしない。適用前に変更内容を確認できる設計にする。

## 6. 次に行う比較：実装前の設計検証

一つの短い単元を使い、「教材を読む→練習→小テスト→課題提出→フィードバック」の同じ目標・内容・評価条件を用意する。Python Labや特定テーマへの依存を避けた最小構成から始める。

1. 教師が担う説明・進行・理解確認・介入を列挙する。
2. 同じ単元を教師伴走型と自学自習型の設計表にする。自習型では教師の働きをどこで補うか記録する。
3. 各方式について、標準Topicsと現行Dual Learningの準備手順・学生導線を比較する。
4. 不足する作成支援は紙面上の手順案として試す。プラグインの効果と文書による補助効果を分けて記録する。
5. 学生として開始・中断後の再開・誤答・未提出・提出後・質問・修了をたどる。
6. 指摘を「教材」「説明書」「Moodle設定」「プラグイン機能」に分類し、最小の次期範囲を決める。

### 観察票

| 観点 | 記録すること |
| --- | --- |
| 作成者の負担 | 所要時間、判断に迷った箇所、調べ物、重複入力、設定の手戻り |
| 公開前の点検 | 開始・終了条件、完了設定、誤答時の案内、質問先の漏れを見つけられたか |
| 学生の行動 | 開始・次の活動・戻り先・提出先・質問先を補足なしに選べたか |
| 状態の理解 | 教材確認済み・小テスト合格・課題提出済み・評点公開を区別できたか |
| 方式の移行 | 口頭説明に依存した箇所を特定し、自習用に補えたか |

実施者のMoodle経験、活動数、利用端末、手順案の有無、試行順序を記録する。同一実施者による反復には慣れの影響があるため区別する。エージェントによる操作確認は予備点検であり、実利用者の観察とは区別する。

### 次期実装へ進む判定基準案

- 両方式で学習者が開始・進行・つまずき時の対応・提出・終了を判断できる。
- 作成者が各設定の目的と、不足している設計項目を説明できる。
- 手順案により迷い・重複作業・手戻りが減る見込みを具体例で示せる。
- 標準の説明書や設定だけで解消できる問題を、不要な独自機能へ拡張しない。
- モード切替時に教材補足が必要な点を示し、記録保持を確認できる。

数値目標は基準測定後に設定する。現時点で改善率や学習効果は主張しない。

## 7. 機能候補と順序（未実装・評価後に選定）

1. 学習形態別の作成手順・チェックリスト：まず文書で試す。
2. 公開前の設定点検：意味のある不足を検出できる範囲を検証する。
3. 両方式で使える質問先の指定：現行のGuided限定表示を再検討する。
4. GuidedからPathへの移行点検：説明・解説・次の行動の不足を案内する。
5. 小テストの状態案内：標準画面で不足することが確認された場合に検討する。

ウィザード、テンプレート、自動設定のどれを採るかは未決定。Canvas等の成長要因の推測は採用根拠にせず、この比較で価値を確認する。
