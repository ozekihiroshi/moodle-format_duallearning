## 進行役の準備

架空の教材を使う隔離テストサイトに、編集教師と別の登録済み学生アカウントを用意する。本番の学生記録は使わない。Dual Learning＋Boost、標準Topics＋Boostの2つの表示コースを用意し、権限・単元数・利用可能な標準Page活動をそろえる。LessonMarkやDual Learningテーマを必須にしない。開始前に教師が標準学生ロールへ切り替えられることを確認し、サイト側の方針が異なる場合は記録する。

同程度の長さの別題材を用意する。試す形式の順序を参加者ごとに入れ替え、順序とMoodle経験を記録する。2回目には練習効果がある。参加者を確保できればスマホとPCを含め、PC上の画面幅変更だけで実機確認済みとはしない。記録は匿名の短い参加者記号とし、学生データを集めない。開始前に目的を説明し、メモを取ってよいか確認する。動画撮影は必須ではない。

## 参加者への課題（クリック手順を教えず読み上げる）

「データ表を確認する短い授業を準備しています。単元の下書きを作り、説明教材を1つ追加してください。未完成の内容は学生から非表示に保ってください。学生から今どう見えるかを確認し、戻って同じ説明教材のタイトルを変更してください。変更を保存できたと思ったところで終了してください。操作しながら、今何が起きていると思うか話してください。」

コピー用の説明本文を別紙で渡す。もう一方の形式では「測定表の単位の確認」など同程度の別題材を使う。先に操作方法を教えたり、押すボタン名を示したりしない。止まった場合は「次に何を試してみようと思いますか」と尋ねてから補助し、全ての補助を記録する。

## 操作後に聞くこと

- 何を作りましたか。もう一度開くならどこを探しますか。
- 今、学生は見られますか。画面のどこを根拠に判断しましたか。
- ロールの確認で、特定の登録済み学生がアクセスできると分かりますか。なぜそう思いますか。
- 本文を直すならどうしますか。取消や戻る操作では何が起きますか。
- どこで迷いましたか。役立った情報、邪魔になった情報はありますか。

終了後、進行役が標準Moodleの操作で保存されたタイトル・活動ID・非表示状態を確認する。別のテスト学生アカウントで、その検証条件における実アクセスも確認する。内容を見るために非表示下書きを学生へ公開しない。本人の推測と進行役の確認結果を分けて記録する。

## 振り返りと次の試作

各試行を「補助なしで完了」「補助ありで完了」「未完了」「未観察」に分ける。クリック数や時間の比較より先に、公開状態の誤解、作業の消失・重複を記録する。反証となる所見も含めて個別の観察を報告し、少人数の便宜的な標本から割合を一般化しない。数値目標は初回観察で基準が分かった後に定める。

各問題は「証拠 → 影響する判断 → 改修案 → 逆効果の可能性 → 次の確認」として残す。順序の影響や標準エディターの違いも明記してTopicsと比較する。課題の成功が支えるのは限定的な操作性の所見であり、認知負荷の低下、授業の改善、学習者の保持を証明しない。参加者の確保と観察は未実施として残し、開発者確認・自動テストは別の証拠として扱う。
