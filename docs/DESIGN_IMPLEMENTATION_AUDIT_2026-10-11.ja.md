# Dual Learning：設計思想と実装の監査

[English](DESIGN_IMPLEMENTATION_AUDIT_2026-10-11.md) | 日本語

2026-10-11。初回監査。コード調査と既存コースの管理者画面観察を実施。初見教師・学習者による評価、標準Moodleとの実測比較、学習成果の評価は未実施。

## 判断の前提

**Less complexity for teachers. More clarity for learners.**

**Every feature must justify its complexity.**

原則は目指す方向であり、達成済みという宣言ではない。既存機能にも適用し、削除・統合・表示整理・既定値の変更を新機能より先に検討する。学習効果は既存研究から借りる設計仮説とし、操作時間やCIの成功から推論しない。[共通開発原則](DEVELOPMENT_PRINCIPLES.ja.md) revision 4 に追加した。

## 対象と証拠の範囲

- ソース：Course Format 0.1.0-alpha10（2026093000）、Theme 0.1.0-alpha7。LessonMarkを必須としない設計も確認した。
- 実画面：localhost:8083、Moodle 5.2.2、既存の教師伴走型コース、管理者アカウント、編集モードOFF。初見教師の代用にはしない。
- 環境差：Formatのマウント先ファイルはalpha10だが、調査時のプラグイン管理情報はalpha8／DB登録2026091901を報告した。Themeは独立リポジトリのalpha7ではなく、moodle-rescue内のalpha5をマウントしていた。公開版の組合せによる受入試験とは扱わない。
- 管理画面では更新確認画面が出たが、コース画面は直接開けた。一括アップグレード、既存教材の変更、公開サイトへの反映は実施していない。

## 五つの観点

| 観点 | 実装で確認できた価値 | 残る検証点 |
| --- | --- | --- |
| 教材作成者 | 非表示の単元から開始し、標準教材フォームへ進み、同じ単元へ戻れる | コース作成自体は標準フォーム。学習形態の選択が加わる。単元のひな型も編集負担になる可能性がある |
| 学習者 | 表示可能な活動と標準の完了状態から次の候補を示す | 完了追跡なしでは候補がなくなる。最初の未完了と再開位置は同じではない |
| 二つの学習形態 | 見出し・ひな型・フォーラムへの近道などが異なる | 両形態とも次の候補は最初の未完了。教師が今日扱う範囲を表す仕組みではない |
| Moodleとの整合性 | Topics・Boostを基盤に標準の教材、権限、提出・評価を利用 | 独自画面から標準画面への移動、サブセクション内の戻り道を検証する必要がある |
| 操作体系の一貫性 | 操作を表示し補足説明を折りたたむ。既存教材を編集できる | 独自単元画面と標準編集画面の併存、目的名と教材形式名の混在、長い教材一覧の下にある追加操作 |

## 優先する検証候補

以下は改修候補であり、利用者の迷いを実測した結果ではない。

1. **作成の入口と戻り道。** `format.php` の作成入口は編集モードと権限に依存する。`unit.php` は既存教材の後に追加操作を置く。空のコースと長い単元の両方で、最初の一歩・次の追加・保存後の位置が分かるか確認する。入口を増やす前に配置と優先順位を見直す。
2. **目的と形式の混在。** `classes/local/unit_actions.php` の近道はPage、LessonMark、Quiz、Assignment。「説明」と「Markdown教材」は同じ教材作成目的の別形式でもある。Forum、File、Bookへの直接の近道はない。標準コース画面からは利用できるため、機能欠落ではなく到達方法の問題として扱う。四つ以上のボタン追加を解決策と決めない。
3. **次の行動の意味。** `classes/local/overview.php::first_incomplete()` は両モード共通。完了追跡なし、以前の未完了、条件付き公開、不合格、表示中の対象すべて完了を別々に試す。「今回」「再開」と実際の選択規則が合うか評価し、まず表示の説明や既定動作を検討する。
4. **折りたたみの判断。** 同ファイルは近道・課題がそれぞれ5件を超えると一覧を折りたたむ。6件になった途端に期限や状態も展開が必要になる。期限が近い課題を見つける作業で比較する。小さく見せることを情報負荷の減少と同一視しない。
5. **サブセクションの一貫性。** `unit_actions.php` の既存教材一覧は対象セクション直下を列挙し、`authoring_navigation.php` は委譲セクションを戻り先から除外する。サブセクション内の教材編集から元の作業へ戻れるか、標準経路と比較して再現確認する。

Themeは主に見た目を担当する。Boostの構造、フォーカス表示、長文の行幅、横幅のある内容のスクロールを支えるが、それだけで設定判断や学習経路が単純になるとは言えない。alpha7のナビゲーション設定を含め、標準Page・Bookで単独利用を評価する。

## 実画面で観察したこと

教師伴走型コースの初期表示では「今回の作業・提出」の下に「作業の入口」「提出物・提出と評価の状態」が折りたたまれ、その下に標準の教材一覧が続いた。コースインデックスも表示された。管理者には同名のLessonMarkと非表示Pageが並ぶ箇所があった。これは既存教材の構成を含む観察であり、学習者にも二重表示されるという意味ではない。

現在の授業位置や初見利用者の理解は、この画面観察だけでは確認できない。管理者の表示を学生のアクセス検証として利用しない。

## 最初のマイルストーン：一つの作成・確認ループを検証する

**まず同じ条件で比較する。** 公開版に固定した隔離環境で、DB登録と実ファイルの版を一致させる。既存教材や現在の環境を一括更新して比較条件を作らない。

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| 基準環境 | Topics＋Boost、Format＋Boost、Topics＋Theme、Format＋Themeを同じ架空教材で用意 | Moodle・PHP・プラグイン版、権限、完了設定、画面幅を記録。LessonMarkなしの組合せを含む |
| 作成者 | 非表示の単元に説明を一つ作り、保存し、学生の表示を確認し、題名を修正して同じ作業へ戻る | 内容と公開状態が期待どおり。戻り先が特定できる。標準の高度な設定にも到達できる |
| 学習者 | 何を学ぶか、次に何をするか、質問先、提出状態を探す | 独立した受講学生アカウントで確認。ロール切替だけで個人のアクセスを保証しない |
| 例外 | 完了追跡OFF、ロックされた活動、未完了の旧教材、6件以上の課題、サブセクション | 誤解しやすい表示や戻り道を再現し、観察と解釈を分けて記録 |
| 改修判断 | 削除・統合・配置・既定値の案を比較 | 対象利用者、価値、増える複雑さ、より単純な代案、未確認事項、受入条件を一件ずつ残す |

[既存の評価手順](AUTHORING_UX_EVALUATION.md)を使用する。観察表には作業、期待結果、実際の経路、立ち止まり、誤操作、ヘルプ要求、遷移、時間、状態の正確さを記録する。比較順序とMoodle経験を記録し、開発者の説明で成功させた場合は援助ありとする。新たな実測値はまだない。

第三者の初見評価は次の証拠である。開発者による再現確認と自動テストで準備を整えた後に実施する。少人数の観察を学習成果や全利用者への効果の証明としない。
