## 評価者に渡す課題

教師伴走型か自学自習型のどちらかを選び、「Pythonで変数の値を確かめる」単元を作ってください。学習者が、説明を読み、短い練習に答え、間違えた理由を確かめ、説明文を提出できるところまで用意してください。最後に本文を一か所直し、作成支援の画面に戻ってください。

教材例（自由に変更してよい）:

```python
x = 3
y = x + 2
print(y)
```

練習の題材: 表示は5になるか。解説の題材: yに代入したのはxに2を足した値。提出の題材: xを4にしたときの結果と理由を2文で説明する。

クリック順のマニュアルは渡さない。必要と感じたときだけ画面内の説明を開いてよい。困ったら止めて、しようとしていたことと見えている画面を伝える。完了時間に制限は設けない。

## 観察者用チェック

- 開始前に経験、選んだ学習形態、端末・画面幅、プラグインのコミットを記録する。
- 初回は空の単元を使い、完成例は先に見せない。学習形態の途中切替は求めない。
- タイトルと学習者向け本文、Markdown教材、練習・誤答時の解説、提出先、学習者表示まで進められたか確認する。
- 再編集と作成支援に戻る操作、説明を閉じたままの作業も観察する。
- 教師のロール切替は表示点検として記録し、本物の学生の提出・評定検証と混同しない。
- 詰まった位置、不要と感じた入力、戻り操作、助言が必要だった場面を記録する。助言した後の完了を「自力で完了」としない。
- 熟練者には別の空単元で同程度の再作成を依頼し、ヒントを読まなくても進められるか観察する。
- 標準Topicsと比較する場合は教材量・題材の難度・利用プラグイン・経験を揃え、順序による慣れを記録する。未測定の削減率は書かない。
