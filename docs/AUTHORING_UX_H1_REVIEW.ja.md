## 所見と変更

従来のコードでは保存した教材に表示・編集リンクが付くが、項目ごとの表示設定がなかった。「表示」も、教師として見ることと学生のアクセス確認を区別していなかった。これはコード点検の所見であり、教師が実際に誤解した証拠ではない。

試作では、教材名、コース・単元・活動の表示設定、利用制限の設定有無と、既存の確認・編集操作をまとめた。コース・単元は非表示の場合に示し、活動の表示設定は常に示す。完全なアクセス可否判定ではなく、設定の表示である。「教師として内容を確認」と明記し、学生ごとのアクセスは別途確認する短い案内を付けた。操作ボタンは狭い画面で折り返し、高さを44 CSSピクセル以上とした。活動フォーム・教材・制限・権限はMoodle標準が管理する。DB構造の変更や他の2プラグインへの依存追加はない。

## 実施した確認

- ローカルMoodle、Boost、登録済み編集教師、標準Pageで、非表示単元の作成 → 教材作成 → 保存・表示 → 単元の作成支援に戻る → 同じ教材を編集 → 名前を変更して保存・表示、を確認した。活動IDは同じで、下書きは非表示を保った。
- 確認用本文は開発者がTinyMCEのソース編集で入力した。初見の教師が補助なしで作成できることの実証ではない。非常に狭い画面では自動操作による標準保存ボタンのポインター操作が安定せず、キーボードのEnterで保存できた。標準エディター・保存操作の実機確認は必要である。
- 英語・日本語を確認。日本語の390 × 844ではページ横方向のはみ出しはなく、変更した2つの操作対象は高さ44ピクセルだった。PC幅も確認した。包括的なアクセシビリティ監査ではない。
- ローカル結合確認：教師の操作、同じ活動への編集先、読取りで活動が変わらないこと、非表示のコース・単元・活動と利用制限の設定表示、学生が非表示教材や作成支援にアクセスできないことを確認した。検証用の一時的な設定変更はロールバックした。12件の確認は全て通過した。
- 変更したサービス・画面・PHPUnitテストファイルのPHP構文を確認した。非表示の上位要素を公開しないことと、制限付き活動の回帰テストを追加した。今回の試作ではPHPUnit一式とホスト側のプラグインCIは未実行であり、ローカル結合確認で代替したとは扱わない。

## 判断と残る課題

H1はレビュー可能なローカル試作として保持する。作成体験のマイルストーン全体を完了とはしない。実際の学生視点の確認、初見の教師の観察、Topicsとの比較は残る。学習成果、認知負荷の低下、時間短縮は測定していない。LessonMark・テーマとの組合せは今回再検証していない。検証経路はBoostと標準Pageで、LessonMarkは導入済みだが使用していない。

リリース前にはプラグインCI一式と実機での動作を確認する。そのうえで、作成者が保存状態を理解し、修正へ戻れるかを評価する。確認のために非表示下書きを公開することなく、誤解のない学生視点の確認へ導線を広げる。H2・H3は別途範囲と検証を定めるまで追加しない。Marketplace公開済み版とAWSは変更していない。
