## Self pacedの結果

1. 学生がsubmission-1.txtをアップロードすると停止しました。ただし、選択画面をCloseで閉じてFilesを押すと保存済みファイルが一覧に現れました。Save changesでは「下書き・未提出」、Submit assignmentとContinueでは「採点のため提出済み」になりました。
2. 概要は「提出済み」と表示し、提出のみの完了条件に従い次の教材を案内しました。返却済み・既読とは表示しません。ただし、返却前でも次教材へ進むため、完了順序と学習上の準備が整ったことは区別する必要があります。
3. 教師がGradeからfeedback-1.txtをアップロードし、同じ復帰操作を経てIn markingで保存しました。学生に切り替えると返却ファイルは表示されませんでした。
4. 教師がReleasedで保存すると、学生の概要に「今回のフィードバックを確認」が現れました。クリックすると標準課題画面のFeedback filesにfeedback-1.txtが表示されました。
5. ダウンロードを操作しましたが、自動操作の完了通知はタイムアウトしました。想定されるローカルの2つのダウンロードフォルダーを対象ファイル名で確認しても見つかりませんでした。サイト側のダウンロード障害と断定はできませんが、取得したファイルの内容は未確認です。
6. 教師がAllow another attemptをYesで保存しました。学生の概要は「再提出が必要」となり、課題が次の操作先へ戻りました。前回分の返却確認操作は出ませんでした。
7. 学生がAdd a new attemptからsubmission-2.txtをアップロードし、同じ一覧復帰を経て下書き保存・正式提出しました。標準画面は今回の提出と過去履歴のsubmission-1.txtを区別していました。新しい返却前でも採点状態はReleasedと表示されましたが、今回の返却ファイルは出ていませんでした。
8. 教師の2回目の返却欄は空でした。feedback-2.txtをアップロードし、一覧復帰後にReleasedで保存しました。学生の確認操作はfeedback-2.txtへつながり、過去の提出は履歴に残りました。コースのパンくずへ戻り、「次に確認する項目」から次教材Page70へ移動できました。

前回の評点なし返却ファイルfeedback-1.txtが標準の過去履歴に表示されない点は、以前の記録と同様です。今回分として混ざることはありませんでした。FILE_FEEDBACK_REVIEW_2026-10-11.ja.mdも参照してください。

## アップロードの停止と比較

毎回、YUIのアップロード用フレームにChromeのブロック表示が出ました。コンソールにはアップロード完了処理で別オリジンのフレームへアクセスしたというSecurityErrorが記録されました。サーバーはアップロードPOSTにHTTP 200を返していました。最初の失敗後の読み取り確認では、33バイトのsubmission-1.txtが学生の下書き領域に存在しました。通常のClose → Filesで一覧へ復帰できました。ブラウザの保護設定やコアコードを変更して応答制限を回避する操作は行っていません。

標準Topicsの課題72でも同じsubmission-1.txtのアップロードで再現しました。Dual Learning固有の問題とは判断できません。ただし、Moodleコアの不具合とも未確定で、Chrome・自動操作接続・検証環境の影響を切り分ける必要があります。最初の拡張機能によるファイル選択拒否は別の問題で、ユーザーによる再接続後に解消しました。その後の操作接続の切断では、新しい検証タブへ移りました。

Topicsはアップロード停止時の選択画面で止めています。同コースの返却・再提出の一巡とTeacher guidedの検証は未実施です。自動操作の影響を切り分けるため、Topicsで手動アップロードしても停止するかユーザーに確認を依頼しました。比較全体が完了したとは扱いません。

## 次の判定条件

アップロード応答の停止を解消または説明できる状態にし、通常のダウンロードで内容を確認してから一巡を合格と判定します。その後、Topicsの一巡とTeacher guidedの導線を続けます。この監査で製品コードは変更しておらず、CIも再実行していません。コードの検証基準は成功済みの907e6b9です。モバイル、支援技術、第三者の利用観察は別途必要です。
