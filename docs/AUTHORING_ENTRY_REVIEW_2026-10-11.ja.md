# 初回の教材作成入口の検証

[English](AUTHORING_ENTRY_REVIEW_2026-10-11.md) | 日本語

2026-10-11。開発側による認知的ウォークスルーであり、初見の参加者による試験ではない。[教材作成の一巡比較](AUTHORING_COMPARISON_2026-10-11.ja.md)の続編。

## 判断

**導線は機能するが、発見しやすさは未確認である。** 両フォーマットから標準のNew Pageフォームに到達した。Dual Learningでは、ユニットが存在しない空コースでも「Continue building a unit」が主な入口になる不整合を確認した。入口改善の第一候補とする。

## 条件

隔離環境8098で、前回比較のリリース版に空の概要欄の候補修正を加えた状態を使用した。新規2コースはBoost・同じ編集教師・英語・Chrome・同じデスクトップウィンドウで比較した。開始時はGeneralのみで、教材も番号付きセクションもない。コース6はTopics、7はDual Learningの既定Self paced。LessonMarkは未導入。

操作者はMoodleと実装を知っている。アカウントは使用済みであり、新規コースの検証であって初回ログインの再現ではない。直前の学生セッションでMoodleツアーが出たが、教師検証前に閉じた。参加者の所要時間・成功率・キーボード限定操作・モバイルの評価は行っていない。

## 観察結果

| 判断点 | Dual Learning | Topics |
| --- | --- | --- |
| 編集オフでどこから始めるか | タブと空のGeneralが表示され、本文内に作成入口はない。標準のEdit modeはある。 | 同様にEdit modeの発見が必要。 |
| 編集オンで何が出るか | Continue building a unit、Start a unit from an outlineの順。標準の追加操作も残る。 | Generalの「＋」から追加メニュー。Add sectionもある。 |
| 主な入口の遷移先 | Continueは候補のない選択画面へ進み、最初のユニットを作るリンクが出る。戻れるが寄り道になる。 | 追加メニューでActivity or resourceとSubsectionを選ぶ。 |
| Pageまでに理解すること | ユニット・アウトライン・題名・学習者向けの例文・非表示の下書き。その後Add an explanation。 | 活動／リソースの種類。19種類の中からPageを選ぶ。検索・分類・説明もある。 |
| 到達先 | Add an explanationで標準New Page。ユニットへ戻るリンク付き。 | Page選択後Addで標準New Page。 |

**作成後の結果は明示される。** Dual Learningでは題名だけ入力し、用意された例文を残してCreate hidden draftを実行した。ユニット作成画面へ直接進み、非表示の確認と、説明・練習・提出の追加操作が出た。今回は教材フォームへの到達を終点とし、どちらもPageは保存していない。

**キャンセル時は画面の種類が変わる。** Dual LearningのPageフォームをキャンセルすると標準のセクション画面へ戻った。そこにもBack to unit authoringはあり復帰できるが、この切替は参加者評価の観察対象に含める。

標準の活動選択画面は、最初のアクセシビリティ操作では開かなかった。同じコースでブラウザの意味に基づくクリックを行うと開いた。製品側の原因を示すコンソールエラーは確認できず、操作自動化の中断は使いやすさの比較から除外する。

## 解釈と優先順位

1. **主操作をコースの状態に合わせる。** 対象ユニットがないときは既存のStartを主にし、Continueを省く。ユニットができたらContinueを残す。標準Moodleの操作は維持する。新しい概念を増やさず、無関係な選択を減らせる。
2. **編集オフの入口を評価する。** Edit modeの発見は両方に必要で、Dual Learningにもその前の目的に沿った手掛かりはない。まず教師が見つけるか観察する。必要なら短い状況説明や権限に応じた直接導線を検討し、常設チュートリアルを先に増やさない。
3. **用語と例文の解釈を評価する。** 説明を一つ追加したい人に、ユニット・アウトライン・What learners will readがどう読まれるか確認する。アウトラインを必須の準備と誤解しないか、ユニット本文とPage本文を区別できるかを尋ねる。混乱を観測した事実ではなく、検証仮説である。
4. **目的で選べる操作と復帰を維持する。** Add an explanationは授業の目的をPageに対応させ、戻るリンクは編集を継続できる。参加者による価値の確認はこれからである。

今回の経路は同じ作業量ではない。Dual Learningは非表示ユニットを作成し、TopicsはGeneralへ追加している。クリック数や速度の優位性は結論できない。非表示下書きの公平な比較には、Topics側のセクション作成・命名・非表示設定も含める必要がある。

## 次の参加者評価

既存の[評価キット](AUTHORING_UX_EVALUATION.ja.md)を使う。編集オフの空コースから「授業の短い説明教材を一つ準備してください。未完成のものは学生に見せないでください」と依頼する。Edit mode・ユニット・Page・ボタン名を先に教えない。最初の操作、停止箇所、支援、例文の理解、入力フォームへの到達を記録し、学生に何が見えると思うか本人に説明してもらう。試す順序を交互にし、同等の題材を使う。結果は支援なし／支援あり／未完了／未観察に分類する。今回の開発者操作を「初見の教師が支援なしで成功」と扱わない。

この検証では製品コードを変更していない。ローカルに2コースを追加し、コース7には確認用の非表示ユニットと例文を残した。以前の4比較コースは変更していない。準備と最終状態はローカル検証領域の `entry-fixture.php` と `entry-state.json` に記録する。

## 実施した改修：状態に合う作成入口

選択可能なユニットがない場合はStartを主ボタンにし、Continueを省く候補修正を加えた。ユニットがあればContinueが主、Startが副になる。判定はユニット選択画面に合わせ、Generalと委譲されたセクションを除外し、非表示の下書きは対象に含める。編集モードと権限の条件は維持した。

隔離環境のBoostコース8で、Chromeから「空コース → Startのみが主ボタン → 作成フォームへ直接移動 → 非表示の下書きを1つ作成 → Continueが主、Startが副」を確認した。標準の追加操作も残った。編集モードを切ると両リンクが非表示になった。PHP構文と差分の空白検査に合格した。今回の変更について自動UIスイートとリモートCIは未実行で、公開版番号と本番環境は変更していない。

これで観察された空コースでの寄り道を解消した。Edit modeの発見とユニット／アウトラインの用語理解は、引き続き参加者評価が必要である。ローカルの候補ソースに反映し、保管済みリリース原本は維持した。

## 継続検証：文章の保存先と途中からの復帰

同じローカル候補版で、ユニットの案内文と別のPage説明教材の区別を開発側から確認した。今回、製品の追加改修は行っていない。

| 場面 | 観察した結果 |
| --- | --- |
| 例文を編集した後、題名を空白だけにして保存 | 題名の検証で拒否され、編集した本文は入力欄に保持された。 |
| 題名を直して下書きを作成 | 編集済み案内文を持つ非表示ユニットが1つ作られた。 |
| Pageの題名と本文を入力してCancel | 標準セクション画面へ戻った。ユニット案内文は保持され、Pageは保存されなかった。作成画面への復帰リンクもあった。 |
| 再度説明を追加し、Save and return to course | Pageが1件保存された。戻り先はセクション画面で、案内文と教材リンクが表示された。 |
| 作成画面へ戻りEdit the unit text | 標準のセクション編集画面では欄名がDescriptionとなる。案内文を修正してもPage本文は変わらなかった。 |
| Moodle APIで最終状態を照合 | Page1件、新規ユニット1件、キャンセル教材なし。セクション・教材は非表示で、独立学生もアクセス不可。 |

証跡はローカル検証領域の `check-recovery.php` と `recovery-results.json` に保存した。コース8・セクション14・教材5を使用し、以前の比較コースは変更していない。ブラウザ操作のタイムアウト時には遷移結果を調べてから再試行した。これは操作自動化の中断であり、参加者の迷いやアプリの故障とは扱わない。

**次に確かめるのは用語の理解である。** 同じ案内文が、作成時にはWhat learners will read、操作リンクではunit text、標準編集画面ではDescriptionと呼ばれる。Add an explanationは別のPageを作る。作成管理画面にはユニットの題名は出るが、保存した案内文そのものは再表示されず、確認にはユニットの表示または編集へ進む。これらは観察した事実であり、初見の教師が混乱するかは未検証である。

呼称が異なることだけを理由に2種類の文章を統合しない。案内文は学習の進め方、Pageは説明教材という役割を持てる。参加者には、最初に入力した文章がどこへ保存されたか、Add an explanationで置き換わるのか追加されるのか、案内だけを直すにはどうするかを尋ねる。理解できなければ呼称の統一や保存先の短い手掛かりを検討する。また、この経路でセクション画面へ戻るSave and return to courseの受け止め方も観察する。現状でも戻りリンクによる復帰は可能である。

今回の操作確認によって参加者評価・モバイル検証・全体CI・新版公開が完了したわけではない。復帰の機能は確認でき、用語の分かりやすさは未検証の設計仮説として残る。
