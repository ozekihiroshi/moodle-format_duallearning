# Dual Learning 学習設計・作成支援仕様

更新日：2026-09-18

状態：オーナー合意に基づく改修要求の基準。画面構成・保存項目・実装方式は詳細設計で確定する。以下の要求は現行alphaの実装完了を意味しない。

## 1. 目的と適用順位

**教材作成の出発点で学習形態を明確にし、その方針に沿った作成支援と学習フォローを、一貫して提供する。**

通常は、作成者が教材を作り始める段階で教師伴走型か自学自習型かを選び、その方針で設計・運用する。途中や作成後の変更は通常フローではなく、例外的な見直しとして支援する。表示設定だけで教育的に異なる教材を自動変換できるとは扱わない。

本書は `PRODUCT_DIRECTION.ja.md` を具体化し、README等の「授業後の復習のために通常モードを切り替える」と読める説明を置き換える。二方式を一つの `format_duallearning` で扱う決定、Moodle標準機能の優先、テーマの独立性は維持する。初期仕様のダウンロード原本は履歴資料として保持する。

## 2. 設計の単位と通常フロー

当面は現行実装に合わせ、コース単位で基本の学習形態を選ぶ。そのコース内の教材・活動を方針に沿って設計する。活動ごとに異なる設計モードを保存する仕組みは、今回の要求に含めない。

1. **選択**：作成開始時に二方式の意味と必要な準備を説明し、作成者が選ぶ。
2. **作成**：選択した方式に沿い、構成・教材説明・理解確認・支援経路を整える。
3. **公開前点検**：機械的な設定チェックと作成者による内容確認を分けて行う。
4. **学習フォロー**：学生が開始・進行・質問・提出・予習・復習へ到達できるようにする。
5. **改善**：方針を維持した教材修正を通常とし、方針変更は別の見直し手順で扱う。

自学自習型にもスタッフへの非同期質問や教師による採点はあり得る。作成者と担当教師は同一人物とは限らない。「教師が担う支援」と「教材内に用意する支援」の分担を明示する。

## 3. 方式別の作成支援と学習フォロー

| 観点 | 教師伴走型の作成支援 | 学生へのフォロー | 自学自習型の作成支援 | 学生へのフォロー |
| --- | --- | --- | --- | --- |
| 開始 | 授業の目的、事前準備、教師が導入する範囲を整理 | 予習範囲・授業で行うことを確認 | 目的、前提、開始手順を整理 | 単独で最初の行動を選べる |
| 進行 | 授業の区切り、実演、活動、提出を整理 | 指定された作業と提出先へ進める | 学習順序、進行条件を整理 | 次の活動と必要な条件を確認 |
| 理解確認 | 問いかけ、観察、練習、評価の役割を整理 | 教師の説明と確認結果を参照 | 練習、小テスト、課題、解説の役割を整理 | 結果に応じて進む・戻る・再挑戦する |
| 質問 | 質問先と対応方法を設定 | 質問経路が分かる | ヒント、戻り先、質問先を設定 | 教師がその場にいなくても困りごとに対処できる |
| 振り返り | 授業後の確認事項と関連教材を整理 | 完了済み教材・提出物・講評へ戻る | 復習先、終了条件、完了後の行動を整理 | 必要な箇所を再学習し到達状況を確認 |

教材の質や理解可能性は、入力欄の有無だけで合格と判定しない。教材内容の生成や教育的評価の自動化を必須としない。

## 4. 共通要求と受入条件

| ID | 要求 | 受入条件 |
| --- | --- | --- |
| LD-01 | 作成開始時の意図的な方式選択を支援 | 新規コースの作成者が、選択の意味と担当する支援を確認できる。既存の既定値を選択済みという意思の証拠にしない |
| LD-02 | 方式別の作成手順を提供 | 両方式の設計表を作成でき、各手順が必要な理由とMoodleの設定先を確認できる |
| LD-03 | 公開前に不足を点検 | 完了設定等の機械判定と説明・解説等の人による確認を別表示し、未確認を合格と表示しない |
| LD-04 | 設計意図と学生の導線を対応させる | 開始、次の活動、つまずき時、質問、提出、終了の各場面で学生が行き先を確認できる |
| LD-05 | 両方式で予習・復習を支援 | GuidedをPathへ変更せず予習・復習できる。完了済みでもアクセス権のある教材に戻れる。予習／復習を第三・第四の設計モードにしない |
| LD-06 | 既存の復習・再開手段を保全 | 現行の完了済み教材へのアクセス、提出・フィードバックへの標準リンクを失わない。未完了項目がゼロでも学び直しの入口を失わない |
| LD-07 | 質問支援を方式と独立して設計可能にする | 自習主体でも質問先を案内できる。質問先なしの場合も支援があると誤表示せず、作成者が支援方針を確認できる |
| LD-08 | 学習状態を混同しない | 教材の手動完了、小テストの結果、課題提出、評点公開を区別する。復習を開始しただけで既存完了や評点をリセットしない |
| LD-09 | 例外的な方針変更を支援 | 両方向の変更で設定上の差と教材点検事項を確認し、適用するか取り消すか選べる。教材の自動適合を主張しない |
| LD-10 | 既存コースとの互換性を保つ | 更新だけで方式・教材・活動・完了条件・利用制限・提出・成績を変更しない。既存コースの設計意図は作成者が後から確認できる |

「戻れる」はMoodleのアクセス権を無視する意味ではない。制限中の教材や提出物を独自経路で公開しない。

## 5. 例外的な方針変更

主導線は通常の作成支援と学習フォローとし、頻繁な切替を推奨しない。ただし設定を不可逆に固定せず、見直しの手段を残す。

- **GuidedからPath**：教師が口頭で補う説明、実演、介入、誤答時の解説、終了判断をどこで補うか確認する。
- **PathからGuided**：授業で扱う範囲、教師の介入箇所、予習・授業・復習の分担を確認する。
- 機械が確認できる設定・参照の不足と、作成者が判断する教材内容を区別する。
- 確認事項を示し、変更対象を説明してから適用する。取り消した場合は元の状態を保つ。
- 保存済みの提出・成績・活動履歴を保持する。モードだけ戻しても、人が編集した教材まで復元できるとは説明しない。

詳細な自動変換・一括書換えは対象外。教材を直す必要性を知らせること自体も有効な支援とする。

## 6. 現行との差と改修順序

現行alphaはコース単位の方式設定と学生向け概要表示が中心。方式別の作成支援・準備状況点検・移行支援は未実装。既存の「完了済み教材へ戻れる」ことを、専用の予習／復習機能一式が実装済みという意味に広げない。

| 段階 | 成果物・対象 | 終了条件 |
| --- | --- | --- |
| A：保全・比較 | 既存の復習／再開導線の棚卸し、一単元の二方式設計、標準Topicsとの比較票 | LD-05/06/08の基準動作と、作成者が迷う判断を記録 |
| B：作成支援の詳細設計 | 作成開始の選択、方式別の作成手順、公開前点検の画面・項目・権限・保存方針 | LD-01/02/03/10を満たす最小案があり、機械判定と人の確認が分かれている |
| C：最小改修 | Bで定めた作成支援と、両方式の質問／予習／復習導線 | LD-04〜08を実画面で検証。既存記録の回帰確認に合格 |
| D：例外支援 | 方針変更前の点検・適用／取消 | LD-09/10を両方向で確認。通常フローより優先しない |

フォーム・ウィザード・テンプレートの採用、保存スキーマ、バージョン番号はBで決める。新規保存項目はバックアップ・復元・Privacy APIへの影響も確認する。独自の成績・提出システムや、テーマ・LessonMarkへの必須依存は作らない。

## 7. 評価シナリオ

同じ小単元の目標と評価条件をそろえ、標準Topicsと改修案を比較する。作成者のMoodle経験、所要時間、迷った判断、調べ物、重複入力、手戻りを記録する。学生側では行き先の判断と必要な補足を記録する。

1. 教師伴走型として作成し、予習→授業→提出→講評→復習まで方式を変えずに進める。
2. 自学自習型として作成し、導入→練習→誤答→解説→再挑戦→提出→復習を進める。
3. 両方式で、中断後の再開と全活動完了後の学び直しを確認する。
4. サポートスタッフがいる自習コースで、質問先を案内する。
5. 既存コースを更新し、教材・設定・学習記録が変わらないことを確認する。
6. 例外として方針を変更し、点検・適用・取消を両方向で確認する。

初期の操作確認と実利用者による評価を区別し、未測定の負担軽減率や学習効果は主張しない。表示・権限・日英文字列・キーボード・小画面・バックアップ復元の回帰確認を改修に応じて実施する。
